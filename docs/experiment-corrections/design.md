# 实验正确性与评价成本设计

## 范围

实验对象为 PhysicianBench 和 MedAgentBench，比较现有六种生成方法。公共 Verifier、各方法题型选择机制和主要算法保持现有行为。FHIR-AgentBench 不纳入本次配置调整与真实实验验收。

## TaskCraft 证据转换

原子结论和深度关系的医疗适配输出包含逐来源证据：每项具有 `source_id` 和对应的事实 `statement`。结论、关系和问题生成阶段的算法结构保持现有行为。

适配层保留模型输出的来源与事实配对，不把完整结论或关系批量复制到多个来源，不根据原始记录自动纠正模型引用。模型提供的错误来源和错误事实保留到公共核验；缺失来源沿用公共评价入口的检查。合并题按 `(source_id, statement)` 去重，保留不同事实。

## 实验状态

任务级 `RunResult`、`EvaluationResult` 的状态词汇保持现有契约。批次分别记录生成阶段和评估阶段的状态及失败数量，最终状态依据阶段结果汇总。

- 完整、合法的生成输出允许少于请求题数，包括合法空批次；单独统计产出不足。
- 生成运行失败、输出无法解析或违反公共输出契约，计入生成失败。预算耗尽但仍有合法批次时保留输出与预算状态；没有可接受输出时记录生成未完成，不能宣告批次完成。
- `EvaluationResult.status == failed` 计入评估失败；评估缺失同样不能宣告批次完成。
- `invalid` 是核验结果；`completed` 且临床求解未完成是求解结果，两者不计入评估运行失败。
- 只有生成和评估均完成且没有未处理运行故障，批次才标记 `completed`。生成失败与评估失败可同时记录，批次跳过判断消费该结果。

内部可恢复调用失败以方法最终输出为准；不能仅凭 trace 中出现失败或 `error` 非空就认定整个生成失败。探索、策略更新及环境故障同样不得被最终完成状态覆盖。

## 统计

生成产出率为实际产出题数除以请求题数。生成失败率以生成尝试为分母，评估运行失败率以应评估任务为分母；预算耗尽、少出题、核验有效率、临床完成率和题型分布分别呈现。

Token 用量只累计真实模型请求。纯工具调用保留工具次数，不计为缺失 Token 的模型请求。用量未知的真实模型请求保留未知标记；部分已知的聚合结果不得被当作完整用量，嵌套账本不得重复累计。

## EnvExplore

每个环境采用独立探索运行，探索患者名单与全部测试批次患者名单不重叠。探索完成后冻结环境指导，保存探索患者、环境、模型配置、用量及完成状态。

测试批次加载同一份冻结指导，不调用探索器。缺失、空白、环境不匹配或未完成的指导不能进入测试生成。EnvExplore 保持固定初始策略和现有任务生成机制。

探索成本单列，在该方法总成本中只计一次；测试批次只承担自身生成和评价成本。配置生成与比较脚本负责探索运行到冻结指导再到测试批次的衔接。

## 公共评分

每道通过核验的题目接受三个独立裁判请求。同一模型可以独立调用三次。每份响应同时包含现有四个质量维度的分数与理由，以及推理深度与理由。

评分标准保持现有定义。每个质量维度和推理深度分别取三份评分的中位数，保留原始裁判分数。复杂度指标继续由代码计算。最终 `quality` 和 `difficulty` 结果结构保持现有字段；每份联合响应的 trace 与 Token 只记录一次。任一裁判未提供完整有效评分时记录评估失败。

联合评分使用同一组裁判配置；相关实验配置统一为三裁判。Verifier、Solver 和 Completion 的职责及输入边界保持现有行为。

## 评分输入

合并评分首先使用完整患者轨迹，单独验证调用合并带来的变化。

精简输入包含题目、参考答案、模型 Evidence、被引用的原始记录、临床上下文、核验结果和复杂度指标。引用记录保持原文；上下文从全部患者记录构建，覆盖诊断与状态、用药及调整、检查结果及趋势、时间和关联就诊，并保留叙述记录中的临床信息与否定信息。不得仅根据模型引用或关键词排除其他记录。

上下文精简使用确定性记录处理，不增加摘要模型请求。不能可靠保留临床信息的记录保留完整内容。精简输入只有在小样本对照通过后才用于正式实验。

## 验证

离线测试覆盖来源与事实配对、错误引用保留、生成及评估失败边界、合法少产出、预算状态、纯工具调用统计、冻结指导复用，以及联合评分聚合与失败行为。

快速真实评分对照从两个环境各选三道已有且通过核验的任务，共六道；复用对应完整轨迹、核验结果和模型配置，不重新生成任务、不重跑 Solver。

三组输入为：分开评分与完整轨迹、合并评分与完整轨迹、合并评分与精简上下文。每组保留相同的三个裁判配置。全部重新评分最多产生 72 次请求；兼容的既有基线评分可复用，并明确记录其来源。

按题目、质量维度和推理深度报告评分差值、实际 Token、请求数及运行失败。对任何中位数变化至少一分的项目检查评分理由；核对精简上下文是否遗漏矛盾证据。出现遗漏或无法解释的评分偏移时，正式实验继续使用完整轨迹。六道题的对照仅用于快速回归，不作为统计等价性的证明。

## 实施边界

实施顺序为正确性与统计、EnvExplore、评分合并、输入精简和小样本对照。代码实施在基于项目当前分支的独立工作树中完成；既有论文改动与历史实验产物保持独立。提交按关注点分层，description 和 body 使用中文。
