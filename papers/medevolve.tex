\begin{abstract}
从纵向电子健康记录（EHR）中为医疗 Agent 生成高质量任务面临挑战：不同患者记录能够支持的临床关系各不相同，而可用工具又限制了证据的检索方式。本文提出 MedEvolve，从任务证据锚定与策略进化两个互补层面改进医疗任务生成。在任务构建层面，双探索将反复出现的临床时序模式与工具访问约束提炼为可复用的指导。在策略层面，反馈驱动的进化进一步将核验与独立解题结果转化为跨患者的任务构建规则和任务方向偏好，而非仅修复单个问题。
在两个基准上，MedEvolve 的核验通过高阶任务产出率均高于基线方法。加入其合成任务后，ACE 与 Reflexion 在官方测试任务上的成功率分别提高 6 和 2 个百分点。
\end{abstract}

\section{引言}

纵向电子病历记录患者多次就诊中的诊断、检查与治疗，是构建医疗 Agent 任务的主要数据来源。MedAgentBench 与 PhysicianBench 在此类环境中评测 LLM Agent~\citep{jiang2025medagentbench,liu2026physicianbench}，但任务通常依赖临床专家设计与审核，难以大规模扩展。自动生成方法中，TaskCraft 从文档内容构建原子任务，经核验后进行深度与宽度扩展，并利用核验通过率优化少样本提示配置~\citep{shi2025taskcraft}；CuES 与 AgentEvolver 从环境交互轨迹中合成任务，并通过执行检查验证可行性~\citep{mai2025cues,zhai2025agentevolver}。上述工作从文档内容或环境交互中构造可核验任务。本文进一步关注多患者纵向病历中的临床事件、时间关系及证据模式，并利用任务核验与独立解题反馈，跨患者更新生成指导和任务方向权重。

纵向病历任务生成面临两个困难。首先，任务是否成立同时取决于病例内容与工具能力：当前患者轨迹无法揭示跨患者反复出现的临床关系及其证据分布，完整轨迹也可能超出输入预算；所需证据能否通过工具检索，还需实际交互核查。其次，不同病例所支持的任务类型与推理要求不同，生成指导需要吸收证据核验和独立解题中暴露的任务构造问题。

本文提出 MedEvolve，通过数据与环境双探索提炼可复用指导，再利用核验与独立解题反馈，跨患者更新生成策略，整个过程不更新模型参数。主要贡献包括：（1）结合临床事件模式与工具访问约束，支持有证据依据的任务生成；（2）利用评价反馈修订自然语言生成指导和任务方向权重；（3）在两个 EHR 环境中评价有效高阶任务产出，并检验合成任务的下游经验学习价值。

\section{方法}

\subsection{问题设置}

给定医疗环境 $\mathcal{E}$ 和纵向患者轨迹集合 $\mathcal{D}=\{X_p\}$，目标是为每条轨迹 $X_p$ 构造医疗 Agent 任务。每个任务由指令 $q$、候选参考答案 $a$ 和来源证据 $e$ 组成。生成过程由策略 $\theta_r=(g_r,w_r)$ 控制：$g_r$ 是自然语言生成指导，$w_r$ 是任务类型和难度方向的采样权重，$r$ 为进化轮次。MedEvolve 先通过探索得到数据指导 $K_D$ 与环境指导 $K_E$，再利用评价反馈更新 $\theta_r$。整体流程见图~\ref{fig:overview}。

\caption{MedEvolve 方法概览。（a）数据与环境双探索形成固定复用的指导 $K_D$ 与 $K_E$。（b）生成器结合患者轨迹、探索指导和当前策略构建任务，经原始记录核验后开展质量、推理深度、独立解题与完成评价；解题 Agent 不接收参考答案和证据声明。（c）评价反馈修订生成指导与方向权重；进化结束后冻结策略，在留出患者上评测。}

\subsection{数据探索与环境探索}

单个患者的轨迹只说明该病例包含哪些记录，难以判断这些记录在整个数据源中属于何种模式，也无法在每次生成时重复读取大量患者。因此，我们在生成之前先进行数据探索，把跨患者的观察整理为可复用的指导。

\textbf{数据探索}针对纵向患者轨迹。探索 Agent 读取多位患者的记录，分析数据的组织方式、时间变化、临床事件之间的关联和证据分布，归纳出不同类型任务所需的信息模式，形成数据指导 $K_D$。$K_D$ 只描述可复用的模式，不包含特定患者的临床事实。

\textbf{环境探索}针对环境接口。探索 Agent 实际调用只读查询工具，记录访问方式、返回结构和交互约束，形成环境指导 $K_E$，用于判断一个问题所需的证据能否通过工具获取。

两类探索在初始化阶段完成，之后的所有轮次中保持不变。

\subsection{任务生成与评价}

对于患者 $X_p$，生成器以 $K_D$、$K_E$ 和当前策略 $\theta_r$ 为条件，按指定的任务类型和难度方向生成 $(q,a,e)$，其中关键事实附带对原始记录的引用。

候选任务随后依次经过核验、评分和独立解题。核验重新读取原始记录，检查证据声明对参考答案的支持；通过核验的任务再接受任务质量和推理深度的评价，并由固定的 Agent 在环境中独立作答。解题 Agent 无法获得参考答案和证据声明。

\subsection{反馈驱动的策略更新}

每轮结束后，系统汇总该轮任务的核验缺陷、质量与推理评分以及解题轨迹，归因得到反馈 $F_r$。归因需要区分任务本身的缺陷（如事实错误、证据不足、题意歧义）、任务带来的真实推理难度，以及模型、工具或环境故障，以避免将执行异常当作任务难度。策略按下式更新：
\begin{equation}
\theta_{r+1}=\mathcal{U}(\theta_r,F_r),
\end{equation}
其中 $\mathcal{U}$ 由 LLM 实现。更新作用于两个部分：一是把具有普遍性的构造经验写入 $g_{r+1}$，调整临床信息的选择、证据的组织和任务设计；二是根据各方向的质量与难度表现调整 $w_{r+1}$，改变后续任务的方向分布。

不同轮次使用不同的患者批次生成任务。完成预定轮次后冻结策略，并在独立的患者集上评测。

\section{实验}

\subsection{评测条件与指标}

\textbf{环境与比较条件。}实验覆盖 PhysicianBench 与 MedAgentBench，分别使用 108 与 100 位具有临床记录的患者，其中 81 与 75 位用于留出评测，其余用于策略进化，两组患者互不重叠。各方法共享留出患者与生成模型 GPT-5.4-nano，每位患者最多生成两道只读任务，固定请求题数分别为 162 与 150。患者划分与信息访问规则见附录~\ref{app:env}。

\textbf{评价指标。}任务先对照原始记录核验，再由 GPT-4o-mini 与 GPT-5.4-nano 独立评价最小充分推理需求，聚合为 1--4 级。通过核验且层级不低于 3 的任务计为高阶题。主要指标为高阶题数及其占固定请求题数的比例，即有效高阶产出率，生成失败和无效任务造成的损失均计入；全部通过核验且具有难度评分的任务的平均层级作为辅助指标。评分与聚合细则见附录~\ref{app:metrics}。

\subsection{实验一：有效高阶题生成}

\section{结论}

本文提出 MedEvolve，将数据探索与环境探索结合，使医疗 Agent 任务生成同时受到患者纵向病历内容和工具证据获取能力的约束，并利用核验与独立解题反馈跨患者更新生成指导和任务方向权重，整个过程不更新模型参数。

在 PhysicianBench 与 MedAgentBench 上，MedEvolve 在六种对比方法中均取得最高的有效高阶任务产出，分别产出 23 道与 77 道通过核验的高阶题。下游经验学习实验进一步呈现了合成任务在部分框架中的潜在价值：加入合成任务后，ACE 与 Reflexion 的官方测试通过率提高，OpenClaw 则下降，体现出框架间的收益差异。这些发现支持将双探索任务生成作为构建医疗 Agent 高阶任务的一种方法，并为研究合成任务与经验学习机制的适配关系提供了实证依据。

\section*{局限性（Limitations）}

下游经验学习实验比较了 20 道官方任务与加入 20 道合成任务后的训练设置，任务数量和组成同时发生变化。等量官方任务及其他生成方法所产任务的对照，有助于进一步区分训练规模与合成任务特性的影响。当前下游结果来自 PhysicianBench 上的单种子、50 道测试题，收益的稳定性及其在其他环境中的表现仍需更多评测。

MedEvolve 的生成指导从特定环境的患者记录与工具接口中提炼，当前独立患者评测考察的是同一环境内的策略迁移。当医疗机构、记录结构或证据检索工具发生变化时，已有指导的适用性及所需调整尚未得到系统评价。

\subsection{证据核验提示词}

核验先逐条重读引用的原始记录，再检查题目及候选答案整体是否成立。以下为当前核验提示词的关键节选。
\begin{Prompt}
只判断当前一条证据声明是否受当前这条原始记录支持。
resource 是从环境按 evidence.source_id 直接读取的原始记录。
逐项核对 statement 中的药物名称、剂量、检验值、时间等事实。

核验题目和参考答案是否受 evidence_records 中的原始数据支持。

\subsection{推理深度提示词}

实验一难度复评使用下列冻结提示词节选。输入包括题干、候选参考答案、证据声明和辅助复杂度信息；评分依据正确满足核心要求所需的最简充分解题路径。
\begin{Prompt}
评估医疗任务正确完成所必需的推理深度，1-4分。
先检查题干、证据和候选答案，找出正确满足核心要求的最简充分解题路径，再按这条路径评分。不能只根据题干宣称需要“综合分析”“制定方案”评分；候选参考答案不自动正确，也不代表唯一解题路径。
1分=事实检索：读取、匹配、计数、汇总记录或复述已明确记载的诊断即可回答。多条重复诊断或记录不自动提高层级。
2分=简单判断：事实结合一条临床规则即可得出核心结论，包括异常判断、药物与适应证的简单匹配、通用检查或管理建议。并列完成多个独立简单判断不自动成为3分。
3分=必要整合：核心结论必须依赖多个独立事实之间的关系，完成时间比较、竞争解释比较或条件推导。指出至少两个不可替代的事实以及它们如何共同改变结论；若删去其中一个关键事实，结论应改变或无法成立。证据多、跨度长、约束多、答案长本身不加分。
4分=决策权衡：需要在多个合理备选方案之间进行患者特异的选择；明确至少两个备选方案、相互冲突的收益风险或限制，以及患者证据为何决定取舍。仅提出检查清单、通用治疗建议、严重疾病需要重视或明显应重估管理，不足以获得4分。
检查捷径：题干是否已给出核心结论；诊断标签是否直接包含答案；是否读取单条记录即可回答；是否只需套用通用建议。按仍需完成的实质推理评分。
reason依次写明：最简充分解题路径；必要事实及关系；捷径检查；为什么满足本层级及为什么不满足更高层级。对于4分必须写出方案、取舍和决定性患者证据。无法从输入确认的病历事实应标明，不得补造。
\end{Prompt}

GPT-4o-mini 与 GPT-5.4-nano 独立评分；两份有效评分取中位数并向下取整，缺任一份则不形成聚合层级。通过核验且聚合层级不低于 3 的任务计为高阶题。

高阶产出率以固定请求题数为分母（PhysicianBench：162；MedAgentBench：150），生成不足与无效任务均不从分母剔除。平均层级仅统计通过核验且具有完整难度评分的任务。

实验一生成与独立解题模型为 GPT-5.4-nano，核验与完成裁判为 GPT-5.4-nano，难度裁判为 GPT-4o-mini 与 GPT-5.4-nano。六种方法共享留出患者、每患者最多两题和公共评价。

TaskCraft 将患者记录与只读 FHIR 工具适配到结论抽取、原子任务生成、核验及深度／宽度扩展；两个扩展分支独立出发并共享生成预算。Workflow 执行定位、生成与筛选；SingleShot 单次生成；SelfRefine 最多三次自评、两次修订，通过后提前结束；EnvExplore 使用环境指导和固定初始策略。MedEvolve 使用双探索及两轮更新后的完整策略。各方法内部调用量不同，此比较不控制为相同计算投入。

\subsection{下游经验学习与官方评测}
\label{app:exp2}

执行模型为 Qwen3.8-27B（UD-Q4\_K\_M 量化），关闭思考，每题模型调用预算为 100，种子为 42。两组从相同初始状态出发，共用 20 道官方训练题；混合组另加入通过核验的 MedEvolve 合成题，GPT-4o-mini 与 GPT-5.4-nano 各生成 10 道。训练后冻结经验，在共同的 50 道官方测试题上使用 PhysicianBench 原生检查点评分；参考答案仅用于评分。

ACE 更新策略手册，Reflexion 保存反思与可迁移经验，OpenClaw 通过原生 Skill Workshop 更新技能。Reflexion 每题读取最多三条相关经验，不保存患者标识、个体临床值或逐题答案。测试期间经验不更新，也不依据评分进行反思或重试。

测试通过率以全部 50 道计划题为分母。ACE 官方组与混合组分别完成 48 与 50 题评分，Reflexion 与 OpenClaw 各组均覆盖 50 题。
