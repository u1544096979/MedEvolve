# 合成任务驱动的 Harness 进化实验

## 1. 实验范围

比较六种方法生成的医疗任务，能否在固定模型权重下，通过 Agent 的技能、记忆或策略更新，提高任务完成能力。

| 项目 | 设置 |
| --- | --- |
| 医疗环境 | PhysicianBench、MedAgentBench |
| 任务来源 | MedEvolve、TaskCraft、Workflow、SingleShot、SelfRefine（配置键 `selfgen`）、EnvExplore |
| 实验基座 | OpenClaw、Hermes Agent、ACE、Reflexion |
| 数据划分 | 70% 合成任务训练集、30% 合成任务测试集 |
| 最终评价 | 合成任务测试集成绩，以及相对初始状态的提升 |
| 运行设置 | 种子 42，重复 1 次，实验组串行运行 |

每个环境包含 24 个进化组和 4 个基座初始状态，两环境共 48 个进化组和 8 个初始状态。基座之间比较相对自身初始状态的提升；任务来源之间在同一基座内比较。

### 数据准备

读取已有任务及证据核验结果，只保留核验通过且完成条件属于只读范围的任务。任务与评测产物按项目共享数据契约解析，保留 `execution_requirement`、`read_only_task`、质量、难度和失败类别；不兼容的历史产物在输入检查时明确报错。各来源选取相同数量的有效任务，数量在运行前固定，不超过最少有效产量。任务先按 ID 排序，再以固定种子抽样与划分；训练数量为总量的 70% 向下取整，其余为测试集，两集合均须非空。

同一环境、同一来源在四个基座中使用相同任务、相同划分和训练顺序。清单记录源文件摘要、选中任务 ID、训练与测试 ID、患者范围和生成成本。

划分以任务为单位，检查重复题目和答案变体跨集合的情况，记录患者重叠范围；共享患者记录的结果解释为同环境任务迁移。未见患者泛化需要患者独立的数据。原生 Benchmark 的题目、答案及反馈不进入任务生成或训练。

## 2. 运行方式

固定各基座程序版本和依赖。每组使用独立配置、经验目录和运行进程，从同一基座的相同初始状态开始；每道题新建会话，跨题只持久化技能、记忆或策略手册。程序共用，实验状态分开。

| 基座 | 程序与实验状态 |
| --- | --- |
| OpenClaw | 固定版本程序；每组独立 `OPENCLAW_STATE_DIR`、`OPENCLAW_CONFIG_PATH`、工作目录与 Gateway 端口 |
| Hermes Agent | 固定版本程序及 Python 依赖环境；每组独立 `HERMES_HOME`，保存配置、技能、记忆和会话 |
| ACE | 固定官方源码及独立 Python 依赖环境；每组独立策略手册与运行目录 |
| Reflexion | 固定官方源码及独立 Python 依赖环境；每组独立经验文件与运行目录 |

OpenClaw 的实验 Gateway 由实验进程直接启动和关闭，使用实验端口；个人 Agent 服务和配置保持独立。Hermes 的实验目录从统一初始模板创建，不从个人配置或记忆克隆；技能从 `skills/` 导出，原生记忆从 `memories/MEMORY.md` 和 `memories/USER.md` 导出并重载。目录隔离用于区分实验状态，不作为操作系统权限隔离。

四个基座各保留一份运行脚本。公共部分只负责读取配置、任务划分、工具桥、评审和结果保存。所有组串行运行，同一基座的程序与依赖固定，运行记录保存版本和配置摘要。

模型直接连接配置好的 API，执行模型与辅助模型显式指定。使用基座原生轮次限制、单题超时和可用的输出 token 限制；执行与学习用量分别从原生日志或 API usage 汇总。后台调用无法完整计数时标记为未知，预算限制不表述为统一硬拦截。

公共评审复用项目运行时的输入预算、完整患者记录选取和上下文超限处理，记录材料缩减情况，保留原始轨迹。受实验脚本控制的辅助输入复用公共预算函数；OpenClaw、Hermes 及官方组件内部的模型调用仍由各自原生机制限制，不视为自动获得项目运行时保护。

医疗工具复用现有工具桥和患者范围限制。训练与合成任务测试明确使用 `get_tools(..., read_only=True)`，禁止 PhysicianBench 写入及 MedAgentBench 模拟 POST。每次尝试创建干净医疗数据库，执行后保留实例，完成训练评审或测试评分后释放；医疗实例管理沿用现有环境服务，逐题实例不进入只读生成流程的共享实例池。

依据：[OpenClaw 多实例配置](https://docs.openclaw.ai/gateway/multiple-gateways)、[Hermes 独立配置目录](https://hermes-agent.nousresearch.com/docs/user-guide/profiles/)。

## 3. 训练流程

训练命令选择环境、基座、任务来源及配置，完成一组训练：

1. 读取冻结清单，创建该组的独立初始状态。
2. 按训练集顺序执行任务，每题新建会话和医疗数据库。
3. 公共评审根据本题答案、查询轨迹、参考答案及证据生成完成反馈，以只读完成条件判定结果。
4. 将反馈交给该基座的学习机制，保存实际经验变更及学习状态，再进入下一题。
5. 达到固定训练轮次后结束学习，停止或等待后台学习结束，保存最终经验快照。

解题输入只有题目、患者标识、必要背景和工具。参考答案与证据只在执行结束后供评审和学习使用。同题解题与反馈可以共用训练会话，下一题不继承完整对话。

### 四个基座的学习机制

| 基座 | 执行与学习 |
| --- | --- |
| OpenClaw | 原生 Agent 执行，反馈后由原生 Skill Workshop 积累技能；记录已更新、未更新、未触发或失败 |
| Hermes Agent | 原生 Agent 执行，通过原生技能与记忆机制积累经验，每题新的解题会话 |
| ACE | 官方 Generator 接入医疗工具；官方 Reflector 和 Curator 根据真实轨迹及反馈更新策略手册 |
| Reflexion | 官方 Actor 与文字反思机制接入医疗工具；训练失败后按固定次数反思和重试，每次重试重置医疗数据库 |

OpenClaw 学习是否触发以锁定版本实际行为为准；每题在后台学习结束或确认未触发后继续，不强行增加模型轮次。超时的学习须停止后才能保存快照或进入下一题。

ACE 按固定轮次调用反思和手册更新组件，使用最终手册。Reflexion 保留官方 Actor、运行循环和反思机制，医疗适配采用模型配置的输入预算，并限制实际模型调用次数；每个 Thought/Action 步骤包含两次模型调用。Reflexion 从训练反思中提炼可迁移经验，保存适用条件、操作步骤和错误教训；跨任务提炼属于实验适配。经验不包含患者 ID、个体临床数值或逐题答案，新题按固定规则读取最多三条相关经验，排序规则及上下文上限在配置中冻结。

环境、工具或模型故障单独记录，不作为临床失败经验学习。任务来源之间固定训练数量、顺序种子、轮次、模型和同一基座的原生限制。

## 4. 测试流程

测试命令读取一组训练产物，分别评价基座初始状态与最终经验状态：

1. 对每道题从对应经验快照复制临时运行目录，创建新会话和干净医疗数据库。
2. 关闭学习与后台经验整理，保留技能、记忆或策略读取，执行一道题。
3. 使用相应评分器完成评分，保存逐题结果；评分结束后释放医疗实例并丢弃临时目录。

| 测试对象 | 评分方式 | 结果含义 |
| --- | --- | --- |
| 30% 合成任务测试集 | 复用公共完成评审，参考答案留在评审进程 | 同一来源生成任务上的迁移表现 |
| PhysicianBench、MedAgentBench 官方任务 | 官方原生评分器 | 真实人工编写任务上的外部迁移表现 |

测试报告合成任务测试集成绩，评价固定轮次后的最终状态，不选择最佳经验版本。初始状态与进化状态使用相同题目、模型、工具说明和执行限制。

OpenClaw 关闭自主学习和后台维护；Hermes 保留记忆读取并关闭写入和整理；ACE 只运行 Generator；Reflexion 只运行 Actor，读取经验，不根据评分反思或重试。合成任务测试仅开放只读医疗工具。临时目录中的运行写入不进入最终快照或下一道题，测试前后核对最终经验摘要。

评分读取本题执行所用医疗实例的状态。测试参考答案、评分结果及完整会话不回流到经验库。

### 原生 Benchmark

通过 `experiments.harness_benchmark` 在相同官方任务上比较初始与最终冻结经验；评分与解题在独立进程中执行，官方资产缺失时报 `benchmark_unavailable`。官方测试按原生要求开放文件交付和医疗操作。数据集、版本、评分规则与运行命令见 [官方 Benchmark 评测](../native-benchmark/design.md)。

## 5. 实现与验收

训练与测试分别提供一条命令，每次选择一个实验组合；批量运行按组合顺序调用相同入口。配置保存任务来源、模型连接、训练轮次、原生限制、目录及版本；API 密钥只通过环境变量传入。

每组产物保存在独立运行目录，包含任务划分清单、配置与版本、训练执行及反馈记录、最终经验快照、合成任务测试逐题结果和汇总。成绩使用相对初始状态的绝对提升，成功率差值使用百分点。重复次数为 1，报告单次数值；患者级配对重采样区间反映测试样本不确定性，不代表多次训练运行的稳定性。

成本分别记录任务生成、训练执行、经验更新和合成测试的调用及 token 用量。有价格时计算金额，缺少价格或 usage 时标记未知；同一任务集被四个基座复用时生成成本不重复累计。

四个基座各自完成以下验收：

1. 医疗工具调用、患者范围限制与任务完成评审可用；合成任务的写入被拒绝。
2. 连续训练两题时会话独立，经验可跨题读取，原始答案与对话不直接传递。
3. 经验保存后可被测试命令重新加载；学习未触发或失败时状态真实可查。
4. 合成任务测试评分可用，评分完成前医疗实例保留。
5. 测试关闭学习，题间临时目录独立，最终经验快照不变；故障与缺失用量明确记录。

替代模型测试验证流程和边界；真实接入验收验证各基座程序的实际行为。四个基座均通过真实接入验收、任务数据齐备且运行模型和预算已授权后，才能启动正式实验。
