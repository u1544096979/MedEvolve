# 合成任务驱动的 Harness 进化实验

## 1. 实验控制条件

### 研究目标

比较不同任务生成方法产出的医疗任务，能否在固定模型权重的条件下，通过 Harness 的技能、记忆或策略进化，提高原生 Benchmark 表现。任务质量评价提供辅助证据，Benchmark 上的进化前后差值衡量任务的实际进化价值。

任务来源为 MedEvolve、TaskCraft、Workflow、SingleShot、SelfGen、EnvExplore；实验载体为 OpenClaw、Hermes Agent、ACE、Reflexion。每个环境分别比较六种任务来源与四个载体的组合。每个载体另设未进化基线。

### 任务与数据边界

各方法的生成策略和任务集先冻结，再进行 Harness 实验。生成阶段自身的患者划分沿用任务生成实验规范；Harness 阶段不另划合成任务测试集，合成任务作为进化数据，原生 Benchmark 作为最终测试。

所有候选共用证据核验规则。只有核验通过的任务进入进化，保留原始产量、有效任务数、无效比例和生成成本。正式比较的任务数以各方法有效产量的共同可用数量为上限，在运行前固定；数量充足的方法按固定种子抽样，不能依据 Benchmark 表现选题。相同任务来源在四个载体中使用同一任务集。

检查生成材料、题目、参考答案与 Benchmark 的重叠。Benchmark 题目、答案、任务变体及执行反馈不进入任务生成或 Harness 进化。共享患者记录的实验需要单独说明共享范围，结果解释为同环境任务迁移；未见患者泛化需要患者独立的测试数据。

### 公平比较

同一环境与载体内，任务来源之间固定初始状态、执行模型、进化辅助模型、任务数量、任务顺序种子、轮次和预算上限。每个组合从独立的初始技能、记忆或策略状态开始，不继承其他组合的经验。

使用已授权的 API 模型，模型权重固定；锁定模型标识和连接配置，禁止隐式切换备用模型。任务执行预算与反思、技能更新预算分别记录，计入总调用和 token 用量。各载体保留自身进化机制，不要求内部调用次数相同。

固定进化轮次和预算后使用最终状态，不根据最终 Benchmark 成绩挑选版本或停止时机。载体之间主要比较各自相对未进化基线的收益；任务来源之间主要在同一载体内比较。

## 2. 四个载体的接入与进化

### 公共环境与反馈

复用现有医疗环境的实例创建、患者范围限制、原生工具和状态读取能力。不同载体使用相同工具语义、输出约束和任务判定规则。每次任务执行从干净环境开始；跨任务保留的是 Harness 经验，不能保留患者环境的写入状态。

解题角色只接收题目、患者标识和环境工具，不接收参考答案、证据列表或完整缓存轨迹。执行结束后，公共评测返回完成情况、必要的状态检查和错误类别；参考答案及证据可用于进化反思，但不能成为下一次解题输入中的逐题答案库。

四个载体保留各自的任务执行与进化机制，共用同一套医疗工具接口、环境实例管理和公共反馈；不将四者的任务执行统一替换为现有固定解题 Agent。ACE 的 Generator 是工具执行部分，其 Reflector 和 Curator 保留官方组件；Reflexion 的 Actor、评估与反思循环以作者源码为基础适配医疗工具。

工具适配将现有环境能力暴露为各载体可调用的接口，不新增医疗操作。工具或模型运行故障单列，不能计作临床难度或有效失败经验。记录任务轨迹、评测反馈、更新前后经验状态及用量。

### OpenClaw

使用原生 Agent 执行任务，以 Skill Workshop 保存和修订可复用医疗工具操作技能。通过插件工具或 MCP 适配公共环境，外部实验入口逐任务调度并收集结构化运行结果。

经验学习具有运行时和任务复杂度触发条件，不能假定每个任务结束后必然更新技能。接入验收须验证批量调用下的原生学习触发和完成状态；任务完成后等待对应学习过程结束，再进入下一任务。未触发学习或未产生更新时记录真实状态，不伪造进化成功。

最终测试关闭自动学习、后台维护和经验写入能力，保留已学技能的读取与调用。技能、记忆快照通过执行权限或隔离存储保护，测试前后核对快照一致性。

依据：[Self-learning](https://github.com/openclaw/openclaw/blob/main/docs/tools/self-learning.md)、[Agent CLI](https://github.com/openclaw/openclaw/blob/main/docs/cli/agent.md)。

### Hermes Agent

使用原生 Agent 与技能、记忆机制执行合成任务，通过 MCP 或自定义工具接入公共环境。程序调用入口负责任务调度与轨迹收集；进化阶段按任务顺序累计经验，不能把所有任务作为彼此隔离且不共享经验的并行请求。

保留原生技能创建、修订与记忆整理机制，记录实际发生的持久化更新。每个任务使用新的解题会话，同时共享本组合的进化状态，避免上一题对话直接成为下一题上下文。

最终测试关闭后台整理、技能管理写入及记忆写入，保留技能和记忆读取。`skip_memory=True` 会同时关闭读取与写入，不能用它替代冻结学习。禁止借助通用文件或执行工具改写经验快照，测试前后检查状态一致性。

依据：[Python 调用](https://hermes-agent.nousresearch.com/docs/guides/python-library/)、[Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/)、[Curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator/)。

### ACE

将 ACE 的 Generator 接入医疗工具执行循环，执行轨迹与公共反馈交给 Reflector，再由 Curator 增量更新策略手册。每个组合从相同初始手册开始，更新后的手册供后续任务读取。

官方离线入口依赖验证集并按验证成绩选择最佳手册。本实验采用其反思和增量更新组件，由公共入口按固定轮次调度，使用最终手册；该适配须在实验设置中明确说明。Benchmark 不传入离线训练入口，也不用于手册选择。

最终测试只加载冻结手册并执行解题，不运行 Reflector 或 Curator，不更新条目计数或内容。

依据：[官方仓库](https://github.com/ace-agent/ace)、[运行与版本选择源码](https://github.com/ace-agent/ace/blob/main/ace/ace.py)。

### Reflexion

使用作者官方源码中的 Actor、评估与文字反思机制。Actor 执行合成任务，公共评测返回完成反馈，失败尝试产生反思并供预算内的后续尝试读取；每次重试重置医疗环境。任务尝试次数与反思次数预先固定，同一载体内各任务来源保持一致，全部调用计入进化预算。

采用跨任务经验迁移适配：从合成任务反思中提炼可复用的医疗工具操作经验，保存到本组合的经验库。经验保留适用条件、操作策略和错误教训，不携带患者标识、个体临床数值或逐题答案。该跨任务经验整理与选择能力属于实验适配，不作为原版 Reflexion 已有机制报告。

新任务按预先固定的选择规则、条数和上下文预算读取相关经验；不得根据任务答案或 Benchmark 成绩选择经验。任务级尝试记录与跨任务经验库分别保存，前一题的完整对话不直接传入下一题。

最终测试冻结经验库，Actor 只读取既有经验并执行任务，不接收评分反馈、不产生新反思，也不根据评分重试。初始状态与进化状态采用相同测试执行预算，主要比较合成任务经验在未见 Benchmark 任务上的迁移收益，而非同题反思重试收益。

依据：[论文](https://arxiv.org/abs/2303.11366)、[官方仓库](https://github.com/noahshinn/reflexion)、[任务级反思与记忆源码](https://github.com/noahshinn/reflexion/blob/main/alfworld_runs/generate_reflections.py)。

### 接入验收

每个载体固定源码版本、依赖与配置后，验证一次完整的工具执行、公共反馈、经验更新、保存重载和冻结测试流程。验收同时检查患者边界、环境重置、答案隔离、预算记录和冻结状态。

四个载体实际医疗环境联调通过后才声明可运行。OpenClaw 和 Hermes 的本机既有安装不能直接复用个人经验状态；实验使用独立配置与存储。Reflexion 接入验收还需验证经验跨任务读取和患者信息隔离。

## 3. Benchmark 测试与结果统计

### 测试协议

在同一原生 Benchmark 的官方测试划分上，分别运行各载体的初始状态与六种任务来源对应的进化状态。使用 Benchmark 原生评分器，保持题目、执行模型、工具、推理预算与环境初始状态一致。

每题重新创建解题会话和环境，并从同一冻结经验快照读取。测试任务之间不传递对话、环境写入或新增经验。参考答案和评分反馈不回流至 Harness。模型或环境故障按原生评分协议处理，同时单列故障数量。

重复运行使用预先固定的种子与重复次数，初始状态和进化状态在相同重复条件下比较。Benchmark 成绩只用于最终报告；观察成绩后调整方案的实验须使用独立最终测试数据。

### 主要结果

报告每个环境、载体和任务来源的原生 Benchmark 分数，以及相对于同载体初始状态的绝对提升。以成功率为指标时，提升使用百分点表示。

结果包括各次重复值、均值与波动范围。统计比较利用同一 Benchmark 任务上的配对结果；同一患者存在多题时，以患者为重采样单位估计不确定性，避免将相关任务当作独立样本。小样本结果仅描述该样本，不宣称稳定泛化收益。

### 辅助结果

任务质量保留证据核验通过率、临床价值、正确性、纵向整合需求、清晰度和固定解题器完成情况。方法名称不进入质量评审输入，不将单次模型评分直接等同于训练价值。

同时报告生成成本、Harness 执行与进化成本、Benchmark 测试成本，以及实际任务数、经验更新次数和失败类别。有配置价格时计算金额，否则报告调用和 token 用量。质量评分与 Benchmark 收益之间的关系作为解释性分析，不能仅凭相关性推断因果。

### 保存内容

保存冻结任务集、任务核验结果、运行配置、源码版本、进化轨迹与反馈、最终经验快照、Benchmark 原始评分和统计结果。任务与患者标识贯穿记录，能够回查每条结果所使用的环境、载体状态和任务来源。
