# Workflow 方法对比规范

## 定义

Workflow 为本实验的“固定阶段生成”方向对比，按本文件定义实现，不对应某篇已确认的论文，也不以论文复现名义报告。没有 MedEvolve 特有的数据探索和跨轮进化。

## 流程

固定执行三个阶段：定位、生成、内部检查。

1. 定位节点读取一个患者的轨迹，匹配给定的五类任务：诊断与解释、检查与风险分层、治疗规划、药物处方、治疗重规划。依据患者事实和证据，选择适合该患者的两个不同题型，分别确定临床关注点与相关 source_id。临床关注点为本次出题的具体主题，不另设预定义分类。
2. 将选出的两类任务分别交给对应题型的生成节点。每个节点使用患者轨迹、该类任务的关注点、引用来源和难度要求，尝试生成一道题及候选参考答案。节点复用同一个生成模型，按题型使用对应提示词；证据不足时允许不出题。两个节点结果合并为最多两题的 TaskBatch。
3. 内部检查节点对合并后的候选统一复验，逐题判断清晰度、题意与候选答案对应、引用是否支持声明，筛除不通过候选。

阶段不回退、不自主重新规划、不跨患者学习。非空完整流程包含一次定位、两次生成和一次内部检查；无候选时跳过内部检查。

定位选型不使用 weight 随机采样。各生成节点输出须在进入复验前通过题型、数量、字段与来源校验；阶段故障返回失败，不能通过筛掉违规候选掩盖故障。复验判定必须逐题覆盖一次，重复或缺失判定均为阶段故障。

## 答案与证据

生成阶段给出候选参考答案；内部检查只保留或拒绝，不改写答案。内部检查引用记录按 source_id 从输入轨迹的 sources 读取，不从格式化轨迹文本反向解析。内部检查结果不等于公共评测通过。方法仅使用输入轨迹，不自行访问环境。

## 输入输出

沿用 [公共规范](../../common/SPEC.md) 的四参数 generate_tasks 入口。Workflow 的 directions 为包含五类任务及各自难度要求的候选方向池；两类目标任务由定位节点选择，公共入口不提前为 Workflow 抽样两个题型。公共输出校验按候选池与定位结果检查题型，每个选定题型最多一题，总数最多两题。题型选择和定位结果保存在 trace 中。

每题包含 instruction、task_type、reference_answer、evidence 和 decision_point，首轮 decision_point 为 null。患者、环境、方法和任务编号由公共入口附加。

公共输出约束、题型定义与评测提示词一致；方法内部提示词体现上述方向区别。运行状态及成本必须包含全部内部调用，不能只保留最后一份模型结果。

## 公共评测接入

保留题目由公共实验入口封装为 Task，调用现有 evaluate_task(task, trajectory, environment, config)。统一经过逐条证据核验、整题支持性核验、质量评价、独立环境解题和完成评价。内部检查不代替公共评测；环境创建、证据读取、工具获取、状态读取和实例释放均复用当前公共实现。

## 文件边界

实现位于 methods/workflow/。不修改其他方法、公共评测或患者划分。复用标准运行层，不创建自己的 LLM 客户端或 Agent 循环。
