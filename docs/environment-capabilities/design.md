# 环境能力与患者并行设计

## 1. 范围与并发参数

同一次实验选择一个任务生成方法，允许该方法同时为多个患者生成任务。六个方法为 `medevolve`、`workflow`、`selfgen`、`singleshot`、`envexplore`、`taskcraft`。患者之间可以并行，各方法在单个患者内部保留自己的阶段顺序、预算和筛选规则。

生成与公共评测独立调度。一个患者完成全部生成阶段、内置自检和候选筛选，输出最终 TaskBatch 后，立即释放生成名额；其任务随后进入公共评测队列，不再占用生成名额。

| 参数 | 粒度与占用周期 | 设置位置 |
| --- | --- | --- |
| `generation_concurrency` | 同时处于生成流程的患者数；从方法入口到最终输出或失败 | ExperimentConfig，正整数 |
| `evaluation_concurrency` | 同时处于公共评测流程的 task 数；从公共核验到完成判定或提前终止 | ExperimentConfig，正整数 |
| `MEDEVOLVE_MAX_INSTANCES` | 同一次实验允许同时存活的逻辑环境实例数，包括启动中的实例 | 沿用现有环境变量；统一约束准备、探索、生成与评测 |

例如 `generation_concurrency=5`、`evaluation_concurrency=2`：最多五名患者同时生成任务，两道 task 同时评测。患者 A 生成结束就能让下一名患者开始，即使 A 的任务仍在评测。两个模型并发参数不等于 Docker 数量。

配置中显式设置的生成、评测并发数优先；旧配置缺少字段时，两者分别回退到有效的 `MEDEVOLVE_RUN_CONCURRENCY`，未设置则沿用默认值 6。运行保存的 config.json 记录解析后的有效值。环境实例额度沿用当前默认值 3。

本方案覆盖单次实验的患者并发与环境复用；不调度多个方法同时运行，不改变 Harness 进化流程。容器额度是本次运行范围内的约束，不能作为多个独立实验进程共享的机器总额度。

## 2. 六个方法的生成适配

六个生成入口均已存在于 main；TaskCraft 的机制、提示与重试逻辑仍在 `codex/taskcraft-baseline` 迭代。方法入口存在与全部环境适配通过是不同状态，验收记录需分别标明。

| 方法 | 单患者的生成流程 | 逐患者生成需要 Docker 吗 | 并发与环境适配 |
| --- | --- | --- | --- |
| `medevolve` | 按同轮策略生成最终任务 | 不需要；环境探索是准备阶段 | 患者并行；同轮使用同一策略，本轮全部公共评测结束后才反馈并更新策略 |
| `workflow` | 定位两类任务 → 分类型生成 → 内部检查与过滤 | 不需要 | 患者并行；内部顺序不变，保留五类候选池选两类和每类最多一题 |
| `selfgen` | 初稿 → 自检 → 必要修订 → 最终过滤 | 不需要 | 每患者独立预算、候选与反馈；完成全部自检修订后才释放生成名额 |
| `singleshot` | 一次调用，自主选题并输出 | 不需要 | 单次生成完成即释放名额；保留允许题型集合、两题可同类型和一次调用规则 |
| `envexplore` | 一次环境探索后，基于固定指导和初始策略生成 | 环境探索需要；逐患者生成不需要 | 探索先完成，再并行生成；不为每个患者重复探索，不加入数据探索或策略进化 |
| `taskcraft` | atomic 候选、width/depth 扩展、内置核验及最终选择 | 需要查询环境；生成工具为只读 | 患者并行且各自拥有 Pipeline、Ledger、随机流及候选池；借用同一干净查询实例，按患者独立绑定工具，保留当前内部调度及重试规则 |

缓存轨迹读取和一次性环境探索属于准备阶段，完成后再启动患者生成；没有必要为不访问环境的生成方法逐患者创建 Docker。TaskCraft 的内置核验属于生成成本，不占公共评测名额，也不能替代公共评测。

共享一个 FHIR 服务不代表共享患者材料或生成状态。每个患者的工具对象、允许患者 ID、模型上下文、预算、轨迹和输出独立；TaskCraft 不共享 Pipeline、Ledger 或随机数对象。

当前 SelfGen 的环境白名单与 TaskCraft 的只读工具声明尚不等于三环境全部适配。对已有支持的环境实施并发与共享；环境能力表描述真实环境语义，不代替方法协议支持验收，不将缺少工具适配记为已支持。

## 3. 公共评测与轮次依赖

所有方法最终输出的每一道 task 都进入同一套公共评测；内部被丢弃的候选保留生成记录和成本，不进入公共评测。生成失败或零题输出记录本次尝试，不补造 task。

| 阶段 | 判定内容 | 后续行为 |
| --- | --- | --- |
| 证据核验 | 逐条读取真实记录检查引用与事实，再核验题目和候选参考答案 | 引用或整体核验不通过则标记 invalid，停止后续评测 |
| 质量与难度 | 事实准确性、临床合理性、证据充分性、题目清晰度；推理深度及证据复杂度 | 质量和难度各保留三次评分及中位数，维持现有规则 |
| 独立解题 | 解题 Agent 接收题目、患者标识、决策点与工具，不接收参考答案和完整缓存轨迹 | 记录实际回答、工具操作与环境状态 |
| 完成判定 | 对照题目要求检查回答、实际提交或数据库变化 | 保存 completed、理由和失败分类；运行故障不作为临床难度 |

评测队列在患者生成完成后接收其最终任务，可以与其他患者生成重叠。每名患者的两道任务分别作为评测队列项目；`evaluation_concurrency` 限制整个 task 评测，不拆成不同角色的独立并发参数。

MedEvolve 保留轮次屏障：本轮患者生成结束、全部 task 评测结束且结果已保存后，才汇总反馈和更新策略。没有跨患者策略依赖的方法不增加此屏障之外的顺序限制。初始策略评测与最终评测仍保留既定实验阶段顺序。

## 4. 固定能力与 Docker 复用

### 4.1 环境能力与统一来源

| 环境 | Agent 的操作语义 | 数据是否变化 | 每个逻辑实例的容器构成 |
| --- | --- | --- | --- |
| PhysicianBench | 查询；POST 真正创建开放类型的资源 | 实际写入数据库 | 一个 FHIR 容器 |
| MedAgentBench | GET 查询；POST 解析并接受请求、保留提交动作 | POST 不持久化；接受提示不能证明写入 | 一个 FHIR 容器 |
| FHIR-AgentBench | 已适配的原生工具仅查询 | 解题工具不写入数据库 | HAPI 与 PostgreSQL 两个容器 |

FHIR-AgentBench 的数据库用于保存种子数据，数据库本身可写不代表 Agent 开放写入能力。`MEDEVOLVE_MAX_INSTANCES` 继续按逻辑实例计数，FHIR-AgentBench 一个实例对应两个容器；验证同时记录实例数与实际容器数，不能将实例额度直接描述为物理容器数上限。

固定能力的唯一来源为 `environments/capabilities.py`。六个方法的生成与内部核验、环境探索、解题及公共评测都接入同一份说明；探索模型只能补充观察结果，不能覆盖真实操作语义。方法提示不另写 MedAgentBench POST 或 PhysicianBench 持久化文案。

每道最终生成题目包含 `execution_requirement`：`read_only`、`submit_request` 或 `database_write`。公共输出校验要求新题填写该字段；旧保存任务可以缺失，由整体核验依据题面补齐。候选扩展、修订和过滤不得丢失字段，方法生成元数据不能覆盖题目实际要求。

MedAgentBench 可生成提交请求题，不能要求资源真正持久化或读取本次新增资源；FHIR-AgentBench 只生成其查询工具能够完成的任务。任务超出环境能力时记录为任务与环境不匹配，不当作临床难度。PhysicianBench 的提交请求也会实际写入，因此不能放入共享查询环境执行。

真实写入仍经 FHIR 服务写入数据库，不改成另存文件或模拟合并读取。

### 4.2 同一次实验的实例选择

| 使用阶段 | 实例选择 |
| --- | --- |
| 轨迹准备、证据核验、TaskCraft 生成查询 | 共享干净的查询实例 |
| MedAgentBench 或 FHIR-AgentBench 的环境探索 | 共享查询实例；模拟 POST 不修改数据库 |
| PhysicianBench 环境探索 | 独立种子实例，允许试写，结束后释放 |
| 查询解题、MedAgentBench 模拟提交解题 | 共享查询实例 |
| PhysicianBench 提交请求或真实写入解题 | 每道任务独立种子实例，读取结果后释放 |

复用并扩展现有 `evaluation/session.py` 的环境会话，使准备、探索、TaskCraft 生成和公共评测经过同一实例额度入口。共享键包含环境名、管理服务地址和固定种子配置，不混用不同环境或种子。无需建立跨方法的服务端租约平台。

共享查询工具在真正发送写入请求前阻断真实写入，不能只靠提示禁止。TaskCraft 保留更严格的生成阶段只读视图，不能因为 MedAgentBench 的 POST 不持久化就为 TaskCraft 生成开放 POST。

整体核验根据题面确定执行要求。生成字段与核验不一致时拒绝任务，不将其路由至共享环境；不能仅按题型或关键词分类。独立写入任务的写前、写后状态与执行记录共同支持完成判定，既有资源不能冒充本次新建结果。

### 4.3 实例额度与清理

实例创建前预留额度，启动中及释放中也占额度；准备、试写探索、生成、核验与解题不能绕过会话另开实例。共享实例有独立的当前使用计数和会话存活周期，查询任务结束只结束借用，不影响其他患者。

额度不足时环境申请等待，等待不会额外创建容器。额度为 1 且独立写入等待时，当前共享查询借用结束后释放空闲共享实例，给独立任务让出额度；后续查询可按需重建。不能持有查询借用再申请独立实例，不能让持续的新查询饿死已有独立申请。

患者生成失败只影响该次尝试；单 task 评测失败只影响该 task。取消或无法继续的运行错误先停止调度，再等待生成和评测任务释放借用，最后关闭会话。释放失败保留具体实例和错误记录，不虚报环境已清理。

## 5. 输出与验证

方向采样在创建并发工作前按患者原始顺序完成；TaskCraft 保留其患者派生随机流，SingleShot 保留自主选题。相同种子的方向分配和任务编号不受完成顺序影响，不要求真实模型并发输出与串行输出完全相同。

生成尝试和最终 task 在生成结束时立即保存，评测结果随对应 task 完成保存，二者通过稳定 task ID 关联。使用现有写入锁，tasks、attempts、evaluations 按患者下标和题下标组织；并发过程不覆盖其他患者的文件或成本记录。

验证覆盖六方法及各自已支持的环境，检查：生成名额在评测等待期间已经释放；生成和 task 评测分别遵守上限；方法内部顺序与预算保持；共享查询不发生真实写入；独立任务从干净种子开始；MedEvolve 轮次屏障正确；取消和失败不泄漏实例。TaskCraft 在研变更合入后重新执行同一套并发、候选字段、预算和只读工具检查，不能沿用旧样本直接宣布新版通过。
