# 主方法生成输入与答案约束

## 生成输入

每个患者一次 LLM 调用，同时生成题目、候选参考答案与证据。轨迹正文保留时间顺序，来源列表保留 source_id 与原始记录的直接对应。生成输入仅包含本批指定方向与策略的 generation_guidance；题型数量按指定方向限制。

## 答案约束

事实查询答案给出记录支持的数值、单位与时间。每条证据声明只包含当前引用实际支持的事实，日期使用临床事件字段，不使用资源更新时间。跨记录结论逐条引用依据；需要比较多个记录才能成立的“首次”“再次”“持续”“改善”等关系写在候选答案中，单条证据只陈述该记录的事实。

临床判断区分患者事实与临床推断，说明判断依据与材料限制；不把活动处方解释为疗效良好，不推断未记录的耐受性。候选参考答案回应明确的题目要求，并允许合理等价方案。

## 本机运行

管理服务为 `http://127.0.0.1:18084`。镜像归档为 `/Users/guagua/data/physical_benchmark_data/physicianbench-fhir-v1.tar.gz`，导入标签为 `fhir-full:v1`。管理服务启动时设置 `MEDEVOLVE_PUBLIC_HOST=127.0.0.1`、`MEDEVOLVE_BIND_HOST=127.0.0.1`、`MEDEVOLVE_CONTAINER_MEMORY=4g`。

实验逐次创建、使用并释放环境，前一个环境释放后才启动下一个；环境测试与实验不并行运行。每个环境使用独立可写层及数据卷。

OpenCode 工具 Agent 使用 JSON object 请求格式，角色指令包含最终输出 schema；SDK 在本地校验返回对象；OpenCode 的 JSON 字符串允许保留未转义换行等控制字符，解析后仍按同一 schema 校验，原始响应留在 trace 中。工具探索和解题保留标准 Agents SDK 执行，不增加答案修复调用。

## 小样本验证

真实模型边界核验：MedicationRequest/1184 的正确日期、20 mg 与每日一次声明通过；错误日期与未记载疗效被拒绝；“Crestor 每天服用一片20毫克药片”被接受为剂量与频次问题的合理等价答案。原始调用保存在 `outputs/physicianbench-flash-boundary.json`。

同一真实患者生成药物处方与诊断解释两题，单次模型调用、零工具调用。药物题的“再次开具”声明因单条记录不足以证明而被拒绝；诊断题通过引用、整体答案核验与质量评价。其工具 Agent 输出中的未转义换行属于协议格式问题；同一原始答案经兼容解析后，公共完成评价判定完成。候选与核验记录保存在 `outputs/physicianbench-flash-sample-local-20261003-143510/` 和 `outputs/physicianbench-flash-sample-local-retry-20261003-144504/`，后者的 `completion_replay.json` 为原答案的完成评价，不改写原失败运行状态。
