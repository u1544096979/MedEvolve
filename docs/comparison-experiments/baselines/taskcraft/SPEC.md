# TaskCraft 医疗适配规范

## 1. 方法定义与源码依据

TaskCraft 是作者源码的医疗环境适配，保留原子任务生成、深度扩展、宽度扩展及内置核验。比较对象为该算法生成病历检索与组合问答的质量、难度及成本；任务基于记录中已有事实，不额外构造治疗决策、处方执行或环境写入算法。

论文：[TaskCraft: Automated Generation of Agentic Tasks](https://arxiv.org/abs/2506.10055)。作者仓库：[OPPO-PersonalAI/TaskCraft](https://github.com/OPPO-PersonalAI/TaskCraft)。固定源码提交为 `1e405e0b02c4738654e2d885b16677b46c9fe969`，本机参考路径为 `/Users/guagua/code/TaskCraft`。项目根目录为 `/Users/guagua/code/MedEvolve`。

算法行为以该提交实际执行的代码为准，论文解释方法目的和结构。代码、注释、论文不一致时分别列明，不根据文字描述自行加强筛选。保留阶段依赖、有效判断分支、提示词语义、参考答案、重试及停止条件。优先复用作者函数；需要移植时提供函数对应关系和适配差异，保留许可证及归属。旧 AgentEvolver 同名实现不作为源码依据。

深度与宽度是原子任务之后的独立扩展路径：深度读取原子父题并增加串行检索依赖，宽度读取多个原子父题并组合子任务。二者不以对方产出为前提，不要求每道最终题同时包含两种扩展。

```text
患者记录 → 结论抽取 → 原子出题与清洗 → 内置核验 → 原子候选
                                                   ├─ 深度扩展
                                                   └─ 宽度扩展
阶段候选与原始答案 → 公共输出映射 → TaskBatch → 公共评测
```

作者提供三个独立生成入口，没有统一的分支调度器或最终两题选择规则。本适配采用固定随机种子决定两条扩展分支的执行次序，并从符合公共输出要求的候选中随机选择最多两题，不设置原子、深度、宽度配额。所有阶段共用实验总预算，不设置阶段预算占比或预留轮数。这些是实验接入规则，与作者算法分别报告，不根据生成或评测结果临时调整。

## 2. 三个流程与内置核验

### 原子任务生成

对应 `gen_atomic_task.py` 的 `get_candidate_tasks`、`get_initial_conclusion`、`generate_initial_question`、`clean_qa`、`filter_atomic_tasks`、`filter_question`，以及 `agent_tools.py` 的 `VerifyAgent.forward`、`recall_score`。

1. 将当前患者可见记录映射为内容 C 和工具可定位的内容标识 ID；按源码分块、抽取结论 A 及关系 R，医疗映射额外附带实际来源标识。
2. 按 ID/R/A 构造问题，执行源码清洗；原子参考答案为 `clean_qa` 返回的 `refined_answer`。
3. 无工具模型作答，再用源码评分提示词判定；`llm_score >= 1` 返回错误，拒绝候选。评分原始区间为 0、1、2，阈值 1 不表述为满分。
4. 工具 Agent 检索并作答，再判定 `agent_score`，保存答案、评分、步骤及执行轨迹。
5. 按源码 `filter_question` 的实际分支处理：核验返回 error 时拒绝；没有 error 时不额外要求 `agent_score > 0`，不启用被注释掉的零工具步骤及更严格评分过滤。

论文描述了工具 Agent 可答、无工具模型不可答的筛选目标，但固定源码没有在原子过滤末端拒绝零分 Agent 答案。本适配保留实际源码判据，公共事实核验另行执行，二者不合并为新的方法筛选器。

### 深度扩展

对应 `gen_depth_based_task.py` 的 `DepthExtend.backward`、`DepthExtend.verify`、`process_single_task`、`depth_extend`。

1. 以父题的内容标识为目标，调用 SearchAgent 反向检索更大范围上下文及其关系；读取 superset 判断结果中的 `new_query` 字段，显式 `invalid` 时拒绝。该字段解析采用第 5 节列明的最小缺陷修复。
2. 根据新上下文、关系和原标识生成辅助问题；辅助问题的答案为原标识。
3. 对辅助问题执行 VerifyAgent；核验返回 error 或 `agent_score <= 0` 时拒绝该次扩展。
4. 将辅助问题替换进入父题，执行源码 `query_compare_prompt` 对应的合并判断；通过后更新完整问题、当前标识和 `valid_hop`。
5. 按 `extended_attempts`、`max_hops` 停止，保存 `full_results` 与 `solve_trajectory`。最终 `golden_answer` 保持原题答案，子问题与中间答案属于轨迹。

医疗记录必须提供辅助问题所需的真实检索关系。没有可检索关系、无法定位标识或核验失败时记录失败，不以增加题干长度、补充常识推理或普通改写代替深度扩展。

### 宽度扩展

对应 `gen_width_based_task.py` 的 `width_extend`、`check_queries`、`retry_predict`。

1. 输入多个原子候选，保留源码传入合并模型的题目、索引、内容标识和 `golden_answer`；不因注释提到排除答案而删去实际传入的答案。
2. 使用源码合并提示词组合 2–3 道相关题，不增加新的事实或任务要求。
3. 按 `check_prompt_1` 判断能否分解回原始子题，仅保留 `state == 1` 的分组。
4. 按 `check_prompt_2` 让无工具模型作答，并对该组 `golden_answers` 评分；保留 `score < 1` 的结果。
5. 按源码分组、分批、重试组织结果，按当前分组读取原始问题及答案，并按候选标识查找评分对象。结果组装与索引采用第 5 节列明的最小缺陷修复；保留子题和答案列表的顺序，不另行生成合并答案。

### 提示词、Agent 与循环参数

作者提示词正文保留，医疗追加内容只描述数据来源、工具能力、患者范围和字段语义，不加入主方法经验、优化示例或新的筛选标准。JSON 输出包装和原生 FINISH 解析属于接口适配，必须保持原字段含义。

| 参数或行为 | 固定源码依据 |
| --- | --- |
| 文本块、结论、原子候选 | `chunk_size=16384`、`max_candiated_conclusions=20`、`max_candidate_atomic=10`，`gen_atomic_tasks` |
| 深度规模 | `extended_attempts=4`、`max_hops=2`，`depth_extend`；合并外层最多 5 次 |
| 单次 Agent 上限 | SearchAgent 默认 `max_step=20`；深度 `max_backward_step=10`、`max_verify_step=10` |
| 评分采样与核验重试 | `recall_score` 默认 3 次判定取有效评分平均；`VerifyAgent.forward(max_retries=3)` |
| 模型与宽度重试 | `run_llm_prompt` 默认最多 3 次调用；宽度含 `retry_predict` 和调用方外层循环，不能统一压成一次重试 |

源码 Agent 的 action step、planning、reflection 与模型请求数不是同一个计数。替换 `oagents` 时逐项核对这些行为、终止后的答案处理和轨迹内容；不能把 10 个 action step 直接宣称为 10 次模型请求的等价复现。并发评分改为顺序执行、文本切分器替换及候选处理顺序的差异也需列明。

模型名称、地址和凭据统一来自实验 generator 配置；源码模型默认值不自动发起调用。缩小候选数或改变上述参数必须在配置及结果中记录，不把小样本设置冒充源码默认值。

## 3. 环境适配接口与公共契约

沿用 contracts、environments、methods/common.py 和公共运行层。环境适配负责将患者材料和本环境工具接入同一算法，不在三个阶段内部重复编写完整环境实现。

代码职责沿用现有方法结构：`methods/taskcraft/__init__.py` 管理公共入口与实例生命周期，`stages.py` 承担三个阶段，`verify.py` 承担源码内置核验，`environment.py` 承担工具绑定和协议映射，`ledger.py` 接入公共累计预算与运行记录。对照作者源码修正行为，必要时调整内部结构，不按环境复制算法。实施时通过 using-git-worktrees 建立或复用隔离工作区；当前主分支的已提交公共层为接入基准，既有方法代码优先复用，旧分支同步困难时可新建 worktree，仅移植方法所需文件。

| 适配职责 | PhysicianBench | MedAgentBench | 后续环境接入要求 |
| --- | --- | --- | --- |
| 当前患者材料 | 公共 PatientTrajectory 与可回查来源 | 同一公共契约 | 提供可见记录、原始来源及明确患者范围 |
| 检索执行 | 当前患者只读函数工具 | 当前患者 GET 动作及 FINISH | 提供本环境原生检索能力，保留工具语义 |
| 结果解析 | 函数返回值、结构化答案及关系对象 | FINISH 答案列表、单个关系对象解析 | 映射为相同阶段字段，不改答案内容 |
| 事实与证据 | 原始记录字段和 source_id | 原始记录字段和 source_id | 标识可定位，记录类型、状态、时间和单位可解释 |
| 执行边界 | 只读工具绑定、患者鉴权、单次及累计限制 | 执行层拒绝写动作、患者鉴权、单次及累计限制 | 同一约束由执行层落实，缺失能力明确报告 |

不要求环境恰好提供九个相同工具名，也不凭环境名称认定其具备深度扩展能力。各阶段依据实际开放的检索能力执行；缺少材料、协议解析失败和关系核验失败分别记录，不能调用其他患者、外部网络或另一个环境补足事实。第三个环境提供后只增加必要适配及验证，不重写三个阶段、不增加预先设计的插件框架。

公共接口保持：

```python
async def generate_tasks(
    trajectory: PatientTrajectory,
    environment: EnvironmentConfig,
    directions: list[GenerationDirection],
    runtime: RuntimeConfig,
) -> RunResult: ...
```

校验轨迹与环境一致，环境创建、工具获取及释放复用公共生命周期。新增环境的底层服务适配由公共环境 section 负责，TaskCraft 只承担方法所需映射与检索约束。原生生成阶段的写入禁止必须由执行路径保证，不能仅靠提示词，也不能改变公共解题 Agent 的写入能力。

### 答案、题型与证据

原子 `reference_answer` 使用源码清洗后的答案；深度使用 `solve_trajectory.golden_answer`，子问题、中间标识及其答案进入 trace，不自动追加为最终回答要求；宽度将其原始答案列表无损序列化为字符串，子问题与答案的对应关系另存 trace。不能为通过公共评测另写答案或用模型补写来源。

`Evidence.statement` 描述原记录确实支持的事实，`source_id` 指向当前患者可回查记录。医嘱不能表述为实际给药，药品规格不能代替剂量，记录时间不能任意改成事件发生时间。深度关系涉及的事实同样需要实际来源。来源归属检查与事实支持性检查分别记录；公共核验对所有方法使用相同规则，不为 TaskCraft 新增专属模型审查环节。

源码没有公共中文题型或方向采样。当前接入沿用公共 directions、最多两题及临床题型配额；原子生成追加合法的 `task_type` 字段，深度继承父题标签，宽度按输入分组第一父题标签映射，同时在 trace 保留全部父题标签及混合来源。上述标签映射属于公共接入，不宣称是作者采样机制，也不据此添加临床操作或改写答案。原子/深度/宽度是生成来源，与公共临床题型分别记录。两个现有环境的 `decision_point` 均为 null。

### 随机调度与候选选择

实验入口把已有 `ExperimentConfig.random_seed` 绑定到 TaskCraft 的生成包装器，公共入口保持四参数调用；不向 RuntimeConfig 加入方法私有参数，不使用进程全局随机状态。患者级随机种子由实验种子、环境名称和患者标识按固定编码及稳定摘要派生；分支顺序与输出选择使用独立的用途标识和随机流，均保存到 trace。不使用跨进程不稳定的内置 hash。

先完成原子生成和核验，再对 `[depth, width]` 作带种子的随机排列。两条分支都读取同一原子候选池，依次执行，不把先执行分支的结果作为后执行分支输入。没有足够父题、没有剩余预算或检索失败时，按实际原因记录跳过或失败，不追加补题。

最终合并三个阶段的候选，固定候选列表的组织次序后用独立随机流打乱。按打乱后的顺序接纳符合公共字段、患者来源及 directions 临床题型配额的候选，达到最多两题即结束；不按生成来源配额、质量评分、解题结果或是否属于扩展题排序。所有未选候选仍留在 trace。固定随机种子保证相同候选列表和配置的调度与选择可重复，不保证模型重新生成相同文本。

## 4. 公平比较、预算与运行结果

遵循 [公共规范](../../common/SPEC.md)。同环境比较固定患者、数据种子、可见范围、generator 模型、外部预算、公共核验和解题配置；TaskCraft 不读取 MedEvolve 的探索指导、策略、历史反馈或进化经验。

阶段全部模型调用、内部判定、Agent 规划或反思、重试及失败尝试计入生成成本。公共核验、质量评价、解题与完成评价计入公共评测成本，不能被内部核验替代。源码单次 Agent 步数限制与公共累计模型及工具预算同时生效，分别记录实际用量及停止原因。

原子生成、两条扩展和内置核验共用 `runtime.budgets["generator"]`，每患者上限为 800 次模型调用与 800 次工具调用。保留源码候选数量、重试和单次 Agent 上限，不额外设置阶段预算份额、扩展预留或生成来源优先级。先执行的分支可能消耗剩余预算，后执行分支因此未完成时如实记录。预算耗尽后停止调用，保留候选及失败成本；不得为凑足题数增加无限补题、切换为 SingleShot 或因结果不佳调整规则。

TaskBatch 最多两题，证据不足允许少出题。预算耗尽后从已通过内置核验的候选中按现有选择规则选出最多两题；有合格候选时状态仍为 `budget_exhausted` 且输出有效 TaskBatch，没有候选时输出为空。公共入口继续执行完整字段、题型配额和题数校验，通过校验的预算耗尽批次进入公共评测，生成尝试记录保留耗尽状态与实际成本；实际超预算、失败状态或非法批次不进入评测。非生成调用仍按公共规则要求 `completed`。有阶段候选不等于整批生成完成。trace 保留全部阶段候选及其原始答案、父题、核验结果、扩展链、来源映射、拒绝与失败原因。成本字段包含 `model_turns`、`tool_calls`、`input_tokens`、`output_tokens`、`total_tokens`，缺失 token 不记为零。

## 5. 源码兼容与验收

### 源码缺陷的最小修复

本适配包含下列明确的字段判断、答案组装和索引修复。修复限定为正确读取源码声明的字段和对应候选，不改变评分提示词、阈值、任务扩展流程或重试上限；全部列入源码兼容说明和实验结果。

| 位置 | 固定源码行为 | 适配行为及影响 |
| --- | --- | --- |
| `DepthExtend.backward` | JSON 解析结果直接与字符串 `"invalid"` 比较 | 读取 `new_query` 字段，显式 invalid 时拒绝；恢复该判断分支，影响深度接纳结果 |
| `width_extend` 最终结果组装 | 多个分组的输出复用循环外最后一组答案及问题变量 | 按当前分组输出答案和原始问题，影响返回的对应关系 |
| `check_queries` 评分索引 | 用 item 的 index 直接索引过滤后的局部列表 | 按标识查找当前评分对象，影响过滤或分批情况下的评分与失败结果 |

医疗内容与工具替换、协议和公共输出映射、上述源码缺陷修复、随机调度及最终候选选择分别归类。实验名称采用 TaskCraft 医疗适配，报告固定提交和全部实际差异，不宣称原环境及逐字源码行为的完整复现。发现额外源码缺陷时单独提出，不自动扩展修复范围。

### 验收要求

1. 提供源码函数到实现的对应表，明确默认参数、提示词、Agent 行为、筛选分支及所有实际差异。
2. 两个环境分别验证原子、深度、宽度机制；真实成功样本须有记录、工具轨迹、父题、原始答案和完整成本。环境实际不支持某阶段时提供具体能力缺口及失败记录，不以模拟成功替代。
3. 验证原子允许无 error 的零分 Agent 结果、深度拒绝非正评分、宽度可分解性及无工具评分阈值；上述三个源码缺陷修复分别验证。
4. 验证患者范围、执行层只读、单次及累计上限、两类协议输出、事实字段和答案映射，以及固定种子的分支顺序、无生成来源配额的选择和完整候选记录；新增环境可仅增加适配，并通过相同阶段契约检查。
5. 完成公共入口及评测联调，报告阶段成功率、实际产出、公共核验结果、解题状态、失败类别和生成及评测成本；深度零产出、模型故障或未完成真实运行不计为该阶段验收通过。
