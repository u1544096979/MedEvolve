\begin{abstract}

在患者纵向病历中自动构建医疗 Agent 任务，既需要识别跨就诊事件中的临床时序逻辑，也需要确保该逻辑在受限的工具环境中具备闭环可检索的证据支撑。本文提出 MedEvolve，通过数据探索提炼临床事件模式，通过环境探索核查工具检索能力，两类指导共同约束生成器围绕真实病程组织问题、参考答案与来源证据。在此基础上，系统结合原始证据核验与独立解题反馈进行错误归因，迭代修订生成规则并动态调整采样配比，实现任务质量与推理难度的协同演进。实验覆盖 PhysicianBench 与 MedAgentBench，结果表明 MedEvolve 显著改善了有效任务产出并提升了高阶推理要求；同时，由该方法合成的任务能够有效沉淀为可迁移经验，在官方基准上实质性增强了医疗 Agent 的下游决策表现。

\end{abstract}
\section{引言与相关工作}

\subsection{纵向病历中的任务生成}

MedAgentBench 与 PhysicianBench 将医疗 Agent 的评测置于可交互的电子病历环境中，要求 Agent 检索患者记录、整合信息并完成临床相关任务（Jiang et al., 2025；Liu et al., 2026）。这类任务的构建需要从病历中选择问题，并确定答案所依赖的记录。随着任务从单条事实查询扩展到多次就诊之间的信息整合，出题依据也从某个明确的数值或事件，转向患者病程中能够被记录共同支持的临床关系。

然而，不同患者的记录能够支持的关系并不相同。有些病例包含连续检查与多次治疗调整，适合围绕指标变化和治疗过程提问；另一些病例集中于单次就诊，或缺少关键时间点，只能支持较局部的判断。即使题型相同，问题所需的时间窗口、背景和证据也会随病例变化。因此，生成器不能仅根据预设题型寻找可填入的内容，还需要先判断当前病历有哪些特点、哪些关系值得提问，再选择相应的任务方向。

这种选择也不能仅由工具使用过程决定。通过查询获得的执行轨迹记录了 Agent 如何访问病历，患者的诊疗轨迹则记录了既有的治疗、检查与病情变化。一次成功检索可以说明相关信息能够获取，却不能说明这些信息已经构成一个有意义的临床问题。例如，围绕治疗调整前后的指标变化出题，除了找到用药和检查记录，还需要识别调整事件、区分比较时段，并判断检查是否能够支撑问题要求的分析。记录更多或调用更长，并不必然带来更深的临床推理。

在问题成立之后，参考答案仍需与提问范围相匹配。事实查询可以由记录中的数值或事件直接回答，治疗规划则可能存在多种合理方案，实际发生的后续处置不能自动成为唯一答案。若任务缺少必要证据，或将观察到的结果误作答案判据，解题失败就可能来自题目本身。生成策略因而需要同时利用任务核验与解题反馈，逐步调整适合不同病例的提问方式，而不是单纯增加问题的复杂度。

\subsection{与已有工作的关系}

TaskCraft 从工具返回内容中抽取候选答案及其关系，构造原子任务，再通过深度和宽度扩展增加检索依赖与组合结构（Shi et al., 2025）。这为围绕已知答案构建多步任务提供了途径，但纵向病历中的出题机会首先取决于病例本身：连续随访、治疗变化或局部就诊记录能够支持不同的问题。即使多个事实都可以查询，它们是否构成同一临床问题、适合哪种推理要求，仍需要结合当前病例判断。医疗任务生成因此需要在扩展问题结构之前，发现病例中可成立的提问方向。

CuES 和 AgentEvolver 从环境交互中提炼任务，分别通过执行指导或参考解检验任务可行性（Mai et al., 2025；Zhai et al., 2025）。这种思路能够发现环境支持的操作，但对于电子病历，相同的查询工具面对不同患者会返回内容和关联程度各异的记录。理解工具如何调用，并不足以确定某份病历适合问什么；成功重放查询也不能单独确认临床解释或答案的合理性。因此，环境探索还需要与患者数据的理解结合，将能够执行的检索过程转化为由当前病例支撑的问题。

MedEvolve 沿这一方向，将病例中的事件关系与工具的信息获取能力共同组织为出题指导，并通过跨患者的任务反馈修订生成策略。本文以任务生成侧的自进化为研究主体，在统一医疗环境中比较生成结果，再通过共同官方任务检验合成任务的下游价值。

\subsection{本文贡献}

本文提出 MedEvolve，以数据与环境双探索指导纵向医疗任务生成。数据探索归纳不同病例中可支持提问的事件关系和证据条件，环境探索识别相关信息的获取方式，两者共同帮助生成器根据当前病例选择问题，而非将所有患者实例化为相同的提问模式。

在此基础上，MedEvolve 通过任务评价反馈推动生成策略自进化。每轮核验、质量评价和独立解题提供患者级反馈，随后被归纳为生成指导与方向权重的修订，使后续出题能够吸收已有病例中的经验，并适应观察到的证据缺陷和推理需求。研究在两个医疗环境中比较任务质量与有效产出，通过组件控制和固定患者上的策略比较考察自进化的作用，并以共同官方任务上的经验学习评价下游价值。

\section{问题定义与方法}

\subsection{任务、指导与策略}

设患者 $p$ 的纵向轨迹为 $X_p$，医疗环境提供访问患者记录的工具集合。一个任务记为 $\tau=(p,q,a,E)$，其中 $q$ 是问题，$a$ 是候选参考答案，$E$ 是由来源标识与事实声明构成的证据集合。解题 Agent 接收问题、患者标识和必要上下文，通过工具作答；参考答案与证据声明保留在评价侧。

双探索得到数据指导 $K_D$ 与环境指导 $K_E$。第 $r$ 轮策略为 $\theta_r=(g_r,W_r)$，其中 $g_r$ 是可更新的自然语言生成指导，$W_r=\{(c_j,d_j,w_j)\}_j$ 是方向列表，分别包含临床题型 $c_j$、自然语言难度要求 $d_j$ 和非负权重 $w_j$。临床题型限定为诊断与解释、检查与风险分层、治疗规划、药物处方和治疗重规划。题型描述问题内容，难度方向描述预期推理要求。

每个生成位置按归一化权重抽样：

\[
\begin{gathered}
\Pr(z=j\mid W_r)=\frac{w_j}{\sum_k w_k},\\
 w_j\geq 0,\quad \sum_k w_k>0.
\end{gathered}
\]

生成器结合抽样方向和当前患者的事件关系选择问题，采样控制题型与推理要求，记录中的证据条件决定具体任务是否成立。

\subsection{数据与环境双探索}

为了在具体患者上选择问题，MedEvolve 首先从进化患者集合中探索可复用的提问模式。数据探索读取纵向轨迹，归纳记录中的事件角色、时间关系和证据条件，将结果表达为自然语言指导 $K_D$。例如，治疗前后变化分析将治疗调整作为事件锚点，将相关检查组织为可比较的证据；只有当前病例具备相应记录时，这一模式才能用于出题。因此，指导保留的是模式的适用条件，具体问题仍由目标患者的记录决定。

这些条件还需要落实到信息获取过程。环境探索通过工具交互识别可访问的记录类型，以及记录定位、关联检索和证据读取的方式，形成指导 $K_E$。生成器同时读取两类指导，将数据中的证据需求与环境中的获取能力结合。初始探索所得的 $K_D$ 和 $K_E$ 在后续轮次中固定复用，任务反馈则用于修订生成指导 $g_r$ 与方向列表 $W_r$。

\subsection{知识引导生成与证据核验}

对患者 $p$，生成器接收预算内轨迹 $X_p$、固定指导 $(K_D,K_E)$、当前生成指导 $g_r$ 和两个抽样方向 $Z_{p,r}$，通过一次模型调用输出候选批次：

\[
\begin{gathered}
\mathcal{T}_{p,r}=G(X_p,K_D,K_E,g_r,Z_{p,r}),\\
 |\mathcal{T}_{p,r}|\leq 2.
\end{gathered}
\]

生成器先在当前轨迹中选择满足指导条件的事件关系，再组织问题、候选参考答案与证据声明。对变化分析，证据需对应事件锚点和比较时段；对临床方案，答案需区分记录事实与推断，并容纳证据支持的等价方案。由此，原始记录支撑任务中的具体结论，探索指导约束关系选择和提问方式。

公共核验从环境读取引用的原始记录，先判断每项声明的来源支持，再判断这些声明是否共同支持问题和参考答案。逐来源核验检查具体事实，整题核验检查证据与提问目标的关系。通过核验的任务进入质量、推理深度与独立解题评价；未通过任务的缺陷原因进入生成反馈。

\subsection{反馈驱动的策略自进化}

生成任务的评价结果为下一轮出题提供修订依据。反馈模型按患者读取轨迹、任务、核验结果、质量与难度评价以及解题记录，归纳质量问题、推理要求、失败原因和修改建议，再将这些发现按类别汇总。按患者分析使反馈能够结合具体记录判断问题所在，汇总后的建议则作用于后续患者的生成策略。

其中，证据不足、事实错误和题意歧义需要转化为提问条件的修订，例如补充必要引用或缩小问题范围。对于核验通过但未完成的任务，反馈进一步结合工具轨迹和质量评价，分析是否涉及检索或推理困难。策略更新模型读取当前策略与这些反馈，通过一次调用输出新的生成指导和方向列表：

\[
\begin{gathered}
F_r=\operatorname{Merge}\bigl(\{\operatorname{Feedback}(X_p,\mathcal{T}_{p,r},V_{p,r})\}_{p\in P_r}\bigr),
\\
\theta_{r+1}=U_{\mathrm{LLM}}(\theta_r,F_r),
\end{gathered}
\]

其中 $V_{p,r}$ 为该患者的评价和执行记录，$P_r$ 为第 $r$ 轮进化患者集合。通过 $U_{\mathrm{LLM}}$ 的修订，生成指导积累事件选择、证据组织和答案表述的经验，方向权重调整后续题型与推理要求的采样分布。策略自进化由此发生在出题侧，解题模型保持固定。

进化患者按轮次划分。每轮完成生成与评价后，更新策略用于下一轮患者；全部轮次结束后冻结策略，再到独立患者集合上生成并评价任务。这样，任务反馈能够参与策略形成，独立评测结果则用于检验冻结后的生成指导。

\subsection{模型与对比方法}

生成比较分别使用 GPT-5.4-nano 和 GPT-4o-mini；同一条件下，独立解题使用对应生成模型。质量与难度各由 GPT-5.4-nano 和 GPT-4o-mini 独立评价，取中位数并向下取整，保留原始评分和理由。核验与完成裁判使用 GPT-5.4-nano。不同评价协议的历史产物不能直接并入同一主比较。

六种方法均接受公共核验与评价，每位患者最多输出两题。TaskCraft 使用原子任务、内部核验及深度和宽度扩展；Workflow 使用定位、生成和内部筛选；SingleShot 直接根据轨迹单次生成；SelfRefine 在当前患者批次内执行自反馈与修订（Madaan et al., 2023）；EnvExplore 用环境探索指导固定策略生成；MedEvolve 使用双探索和跨患者反馈更新。SingleShot 自主选择题型，Workflow 从题型候选池选择，其余方法按抽样方向构建任务；这些内部选择规则是方法差异的一部分。

输入轨迹按上下文预算选取，原始来源保留用于核验。相同题数上限不构成相同计算预算，方法内部探索、核验、修订和策略更新的实际调用分别统计。独立评测使用冻结策略的生成指导，并固定初始方向列表与抽样种子，以控制任务方向构成。医疗适配与内部预算见附录 C。

\subsection{评价指标与统计}

评价从请求的任务数量开始，依次记录实际生成量、核验覆盖和核验通过量。生成覆盖率以请求题数为分母，核验通过率以具有核验结果的题数为分母，生成不足、评价缺失和运行故障分别统计。由此可以区分方法能否产出任务，以及产出的任务是否具有证据支持。

对于核验通过的任务，质量评价从事实准确性、临床合理性、证据充分性和题目清晰度四个维度给出 1–5 分，并报告各维度均值和分布。推理深度分为事实查询、单步推理、整合推理和临床决策四级，第 3–4 级记为高阶推理。高阶占比附相应任务数量，去重引用数、资源类型数和引用记录时间跨度则用于描述这些任务的证据结构。

独立解题进一步评价任务在给定模型和预算下的完成表现，完成率分别以实际生成任务和具有完成评价的任务为分母。为了将这一表现与投入联系起来，生成成本统计探索、方法内部生成与检查、反馈及策略更新，公共核验、评分和解题成本另列。各阶段报告调用次数和输入、输出 token，并以核验通过题数归一化生成成本；未知用量保留缺失状态。

上述指标采用患者簇重采样估计区间，以保留同一患者多道任务之间的相关性。统计方案进行 1,000 次有放回重采样，种子为 42，使用 2.5\% 与 97.5\% 分位数构造 95\% 区间；相同患者上的方法差异保持配对。评分覆盖、时间可解析覆盖和有效重采样次数随指标报告。正式统计结果尚未填入，评分尺度、分母和具体规则见附录 D。

\subsection{下游经验学习}

为了检验生成任务是否有助于经验学习，下游实验固定模型权重，将六种来源的合成任务分别接入 OpenClaw、Hermes Agent、ACE 和 Reflexion（Shinn et al., 2023）。每个环境包含 24 个来源与 Harness 组合；来源差异在同一 Harness 内比较，以各 Harness 的统一初始状态为参照。

为控制训练样本数量，每个来源仅纳入核验通过的只读任务，选取相同数量且不超过最小有效产量。以种子 42 按任务划分 70\% 训练集和 30\% 辅助测试集，训练数向下取整。PhysicianBench 冻结配置每来源 25 题，其中训练 17 题、辅助测试 8 题，使用 GPT-4o-mini，训练一轮。其他环境的实际数量和模型以其冻结清单为准。四种 Harness 共享同一来源的任务、划分和顺序。

训练时每题新建会话与医疗实例，参考答案和证据只在执行后供评审与学习使用，跨题保存技能、记忆或策略手册。训练结束后冻结经验，不依据测试成绩选择版本。测试关闭经验写入和后台学习，每题从冻结快照开始，使用新会话和独立实例。具体学习机制与限制见附录 E。

各组完成训练后，主要评价采用同一环境的共同官方任务，并使用官方原生评分。对官方任务集 $B$ 和经验状态 $h$，定义完整计划任务口径的成功率及百分点变化：

\[
\begin{gathered}
A(h)=\frac{N_{\mathrm{confirmed\ success}}(h)}{|B|},\\
\Delta_m=100\bigl(A(h_m)-A(h_0)\bigr).
\end{gathered}
\]

其中 $h_0$ 和 $h_m$ 分别为初始与来源 $m$ 训练后的经验。分子为获得有效评分且判定成功的任务数，分母为全部计划任务数；运行与评分故障单独列出，不能据该比率将故障归为临床失败。初始与最终均有有效评分的同题配对子集另报变化与区间，同时保留完整覆盖口径。

\section{讨论与结论}

\subsection{讨论}

不同病例提供的出题机会各异，使生成指导需要同时具有可复用性和适用条件。MedEvolve 以自然语言表达临床模式及其证据需求，使同一模式可以在满足条件的患者上形成具体问题，也允许生成器在其他患者上选择不同方向。随着进化患者提供更多任务反馈，生成策略进一步吸收对事件选择、证据组织和答案表述的修订。指导能否被遵循、能否在新患者上发挥作用，由任务评价和控制实验检验。

这种生成侧的变化还需要与下游学习效果联系起来。质量与证据结构评价反映任务的构建水平，共同官方任务则检查由这些任务积累的经验是否有助于解题。两类结果共同决定任务来源的价值；较高的推理层级本身不足以说明学习收益，单个下游成功案例也不能代表整体效果。

\subsection{结论}

本文提出 MedEvolve，通过数据与环境双探索识别适合不同病例的提问模式，并利用任务评价反馈推动生成策略自进化。生成器结合模式的证据条件和当前患者记录构建任务，策略则在跨患者反馈中修订出题指导与方向权重。研究以生成比较、组件控制和共同官方任务分别考察任务构建、策略自进化及下游价值，正式实验结果尚未填入。

\section*{局限性（Limitations）}

病例记录的完整性、时间信息和模型输入预算限制了可发现的提问模式，轨迹裁剪也可能遗漏关键依据。同一环境内的患者独立划分只能检验该环境中的迁移，跨机构或跨数据来源的泛化仍需另外评价。当前生成采用回顾性信息访问，不启用时间视角隔离，因此不代表临床当时可获得的信息范围。

这些数据限制也影响自动评价。两个模型的评分聚合不能消除共同偏差，现有记录未必足以判定所有临床方案；质量评分又仅覆盖核验通过且评分成功的任务，复杂任务可能因单条引用失败而被整体拒绝。因此，评分均值需要结合评价覆盖和有效产量解释。

对策略自进化的解释同样受比较条件约束。独立评测固定方向配比，主要检验生成指导更新，未覆盖更新后方向分布的整体效果。反馈模型给出的归因和建议也可能有误，策略更新不保证后续结果单调改善。

下游实验中，合成训练与辅助测试按任务划分，可能共享患者，官方测试也可能与经验训练共享底层记录。当前单种子、单次训练配置不能衡量跨运行稳定性，患者簇重采样仅反映测试样本不确定性。不同 Harness 的原生学习触发和调用限制存在差异，任务来源的比较因而限定在同一 Harness 内。

\section{探索与生成接口}

\subsection{数据探索}

探索工具提供开放患者名单、预算内轨迹及可选压缩摘要。输入材料保留患者标识、原始来源和覆盖标记，输出为不绑定患者的自然语言指导。指导归纳数据组织、时间变化、事件关系、证据引用与可支持的问题，不保留个体临床值或来源编号。

压缩摘要用于定位模式，原始记录用于支持具体事实。记录缺失与材料裁剪分别解释。指导中的时间窗口、记录数量或临床关系属于模型归纳的提问约束，不构成对所有患者统一适用的硬编码医学规则。

\subsection{环境探索}

环境探索在独立实例中访问开放患者的原生只读工具。指导记录已验证参数、返回结构、分页与裁剪行为、典型检索方式，并区分调用失败和未验证能力。环境内的具体患者观察不进入通用指导。

\subsection{任务生成与策略}

任务包含患者标识、临床题型、问题、候选参考答案、来源标识与逐来源事实声明，以及执行要求；当前公共生成接口要求时间视角字段为空，执行要求为只读。生成调用输入预算内轨迹、两类探索指导、当前生成指导和两个采样方向，输出最多两题。

生成策略由自然语言指导和方向列表组成；方向包含五类临床题型之一、难度描述与非负权重。方向按权重采样，允许同一题型对应不同临床模式；至少一个权重为正。数据与环境指导在策略更新期间固定，更新只修订生成指导和方向列表。进化阶段按当前方向权重抽样；独立评测固定初始方向列表与抽样种子，读取当前策略的生成指导。

\section{环境、患者与信息访问}

PhysicianBench 的生成患者池为 108 人，MedAgentBench 为官方范围内的 100 人。按种子 42 和既有探索暴露约束冻结进化与评测名单。进化患者分为互不重叠的两轮：PhysicianBench 为 13 与 14 人，MedAgentBench 为 12 与 13 人；评测患者分别为 81 与 75 人。

原始轨迹按记录时间组织，模型输入按预算选取；证据核验读取原始来源，不以输入摘要替代来源。初始探索和任务生成只开放查询工具。解题工具依环境与任务执行要求提供，经验训练的合成任务进一步限定为只读。当前公共生成接口未启用时间视角属性，问题中的时间限定不等同于服务端隐藏后续记录。

经验学习另按合成任务划分训练与辅助测试，不能与生成侧患者划分混用。冻结清单记录选中题目、患者、训练与测试划分、文件摘要及生成来源。官方任务评测另记录任务版本、患者范围及与经验训练的重叠。

\section{生成方法与预算}

TaskCraft 将患者记录与只读 FHIR 工具映射到原方法的结论抽取、原子任务生成、核验与扩展流程。深度和宽度分支均从原子任务出发，彼此没有先后依赖；两条分支共享生成总预算。原子、深度和宽度候选的实际产量及接纳情况分别记录，以区分扩展机制和最终筛选的影响。医疗适配与原论文完整实验复现分别解释。

Workflow 固定执行定位、生成和内部检查，检查只筛选候选。SingleShot 根据轨迹单次生成最多两题。SelfRefine 在同一患者批次内执行初稿、自反馈和修订，最多三次自评、两次修订，全部通过时提前结束。EnvExplore 先获取环境指导，再用固定初始策略生成任务。各方法共享输出结构和公共评价，内部调用与筛选记录分别保存。

主方法初始探索完成后执行两轮生成侧策略进化，每轮按患者归纳反馈并汇总更新。批次输出的结构或配额校验失败保留为生成失败。反馈和更新调用失败不视为进化成功。输入裁剪、实际调用与预算耗尽分别记录。

模型路由、上下文上限、输出限制和工具预算以冻结运行配置为准。同一比较中报告各方法预算与实际用量；相同出题数量不表述为严格相同 token 预算。探索和更新计入主方法总成本，公共评价成本单列，历史复用调用按原始记录去重计数。

\[
\begin{gathered}

\end{gathered}

\[
\begin{gathered}
