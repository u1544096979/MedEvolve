\begin{abstract}

纵向医疗记录中的信息分散在不同就诊、时间点和资源类型中。自动构建医疗任务需要发现有意义的临床关系，并使问题、参考答案与可访问证据相互对应。本文提出 MedEvolve，一个数据探索驱动的医疗任务自进化框架。数据探索归纳轨迹中的事件关系与证据约束，环境探索识别工具能力与检索边界，两类知识共同指导任务生成。随后，框架结合证据核验、质量评价、推理深度标注与独立解题反馈，更新生成指导和任务方向的采样配比。实验设计覆盖 PhysicianBench 与 MedAgentBench：实验 1 比较生成任务的可靠性、推理要求、有效产出和成本；实验 2 在模型权重固定的条件下，将合成任务用于 Agent 经验学习，并通过官方任务评测考察其下游价值。

\end{abstract}
\section{引言}
\subsection{研究背景与动机}
基于大语言模型的医疗 Agent 可以通过工具访问电子病历，检索患者信息并完成医疗问答。面向纵向病历的任务要求 Agent 在多次就诊、不同资源类型与分散记录之间组织证据，并理解临床事件的时间关系。因此，这类任务的构建不仅涉及自然语言问题的生成，还需要明确问题所依赖的患者信息、证据范围与答案依据。

人工编写任务能够针对具体场景设计问题，但逐一梳理病历、选择提问内容和核验答案需要投入较多工作。随着数据环境和患者轨迹变化，任务集也需要持续更新。自动任务构建由此提出一个研究问题：如何从已有医疗数据中发现值得提问的临床过程，生成有证据支撑的任务，并使任务分布随解题能力的变化而调整？

\subsection{医疗任务构建的挑战}
这一问题包含三个相互关联的挑战。首先，任务机会的发现需要理解数据本身。不同医疗环境在资源类型、时间字段、记录密度和临床信息表达方式上存在差异；能够形成有效任务的事件链，需要结合具体患者轨迹识别。例如，围绕用药变化提出问题，需要判断相关记录是否包含足够的时间信息与临床证据。仅确定题型或生成问题文本，尚不足以保证所需证据存在于数据中。

其次，任务需要具有明确的证据依据与可核验的答案。问题文本、可访问记录和参考答案应当相互对应，避免生成缺少支持或含义不明确的问题。对于涉及特定时间视角的任务，还需要明确可用信息的范围，区分作答时能够获取的证据与评估侧用于核验的后续记录。

最后，任务生成策略需要响应解题反馈。通过核验的任务仍可能集中于解题 Agent 已掌握的能力，也可能因证据检索、信息整合或时间推理要求过高而难以完成。解题失败本身不能直接说明任务具有学习价值，还需要区分任务缺陷与解题能力不足。如何利用核验结果和失败归因，调整后续生成指导与任务配比，是持续改进任务生成的关键。

\subsection{核心贡献}
针对上述挑战，我们提出 MedEvolve，一个数据探索驱动的医疗任务自进化框架。框架将对长程轨迹的理解与对工具环境的验证结合，归纳可跨患者复用的生成指导，并通过任务质量、推理深度与解题反馈迭代调整生成策略。

本文的核心贡献体现在方法创新与学习机制两个层面：

\begin{enumerate}
\item \textbf{数据-环境双探索机制。} 患者轨迹的时间跨度可达数年，记录分散在多次就诊和不同资源类型中，任务所需证据可能跨越多个时间点与资源类型。MedEvolve 将轨迹中的事件关系与工具检索边界共同纳入任务机会的识别。MedEvolve 通过数据探索归纳临床事件关联（如"用药调整与指标改善"需要哪些记录、多长时间跨度），通过环境探索验证这些信息的可获取性（工具能否检索、如何组织调用），将两类知识联合建模为任务生成指导。
\item \textbf{反馈驱动的策略进化机制。} 解题失败本身不能直接说明任务具有学习价值——任务可能因证据不足而无法完成，也可能对解题 Agent 要求过高。MedEvolve 设计独立的质量评价、推理深度标注与完成表现分析，区分任务缺陷与能力不足，并将反馈转化为生成指导的更新与题型难度配比的调整。这使框架能够持续改进任务构建方式，而不是简单积累未通过的题目。
\end{enumerate}
\section{相关工作与问题定义}
\subsection{相关工作}
\textbf{医疗 Agent 与交互式评测。} MedAgentBench 将医疗任务置于可交互的电子病历环境中，评估 Agent 通过工具访问患者记录并执行临床相关操作的能力。PhysicianBench 进一步关注真实病历中的长程复合工作流，通过结构化检查点核验任务执行。这些工作为研究医疗工具使用与纵向信息整合提供了环境和评估基础。MedEvolve 关注如何利用环境中的患者轨迹构建任务，并通过反馈持续改进任务生成策略。\href{https://arxiv.org/abs/2501.14654}{MedAgentBench}，\href{https://arxiv.org/abs/2605.02240}{PhysicianBench}。

\textbf{自动任务构建与环境探索。} TaskCraft 从原子任务出发，通过深度扩展和宽度扩展构建具有多步检索与组合要求的 Agent 任务，并结合核验获得任务及执行轨迹。CuES 通过好奇心驱动的环境探索，将交互模式抽象为任务，并结合指导与质量控制生成可执行任务。这些研究说明，任务结构可以从数据关系或环境交互中获得。MedEvolve 在长程医疗轨迹中结合数据探索与环境探索，将对临床记录、事件关联和工具使用方式的理解转化为出题知识，并以任务反馈更新生成策略。\href{https://arxiv.org/abs/2506.10055}{TaskCraft}，\href{https://arxiv.org/abs/2512.01311}{CuES}。

\textbf{反馈驱动的 Agent 改进。} Reflexion 将任务反馈转化为语言反思并保存在记忆中，指导后续尝试。AgentEvolver 将自主出题、经验引导和贡献归因结合到 Agent 学习框架中，连接任务生成与能力改进。MedEvolve 将反馈用于医疗任务生成侧：核验与解题结果帮助识别任务缺陷及能力需求，并为后续探索和出题策略更新提供依据。本文通过任务质量、推理深度、完成表现与成本评价这一过程。\href{https://arxiv.org/abs/2303.11366}{Reflexion}，\href{https://arxiv.org/abs/2511.10395}{AgentEvolver}。

\textbf{MedEvolve 的定位。} MedEvolve 以纵向医疗记录中的临床关系及其证据要求为任务构建依据，同时用工具交互检查信息获取方式。表 1 比较三类方法的任务构建机制。

\subsection{问题定义}
给定一个通过工具接口提供长程医疗轨迹数据的可交互环境、固定的解题 Agent 和生成预算，我们研究如何自动构建可核验的医疗任务，并迭代改进任务生成策略。患者轨迹包含随时间积累的就诊、检查、用药及其他临床记录，环境接口提供记录检索与详情读取等操作。任务生成需要同时确定提问内容、允许访问的数据范围以及参考答案依据。

将一个任务记为 $\tau=(p,q,a,E)$，其中 $p$ 为患者，$q$ 为自然语言问题，$a$ 为候选参考答案，$E$ 为支持问题与答案的证据集合。解题 Agent 接收问题与患者上下文，通过环境工具获取作答所需信息；参考答案和证据标注保留在评估侧。

生成策略 $\theta=(g,w)$ 包含生成指导 $g$ 与题型难度配比 $w$。在固定评估流程与解题配置下，我们研究探索所得知识与任务反馈如何改善生成质量，并改变任务的推理要求和证据结构。任务质量、推理深度与解题完成表现分别评价，避免将解题失败直接视为任务价值。

\subsection{任务与评估约束}
策略进化与独立评测使用互不重叠的患者集合。同一患者的记录不跨集合，独立评测结果不参与策略更新。各环境的患者规模与抽样规则在实验设置中报告。

任务依据环境中可访问的患者记录构建。涉及临床判断时，参考答案需要区分记录事实与合理推断，并允许证据支持的等价方案。实际发生的后续治疗可以提供背景，但不能直接构成唯一正确的临床方案。任务可附带时间视角属性；是否启用及其访问约束由环境与实验配置确定。本文区分实际启用的访问范围与问题文本中的时间限定。

盲测不向解题 Agent 暴露参考答案或证据标注。不同方法与进化轮次使用一致的核验规则、评分标准和解题配置，环境或模型故障单独记录。

\section{方法}
\subsection{整体思路}
长程医疗轨迹中的记录数量与类型并不能直接决定值得提出什么问题。任务生成既需要识别临床事件之间的联系，也需要理解这些信息如何在交互环境中获得。MedEvolve 将这两类理解转化为生成指导，再利用任务反馈调整指导内容与任务分布。

设数据探索与环境探索所得知识分别为 $K_D$ 与 $K_E$，第 $r$ 轮生成策略为 $\theta_r$。对患者轨迹 $X_p$，任务生成可表示为

\[
\mathcal{T}_{p,r}=G(X_p,K_D,K_E;\theta_r).
\]
初始探索提供跨患者的知识基础，具体任务仍由当前患者的真实记录支持。每轮任务经过核验、质量与难度评价以及独立解题，形成反馈 $F_r$，随后更新策略

\[
\theta_{r+1}=U(\theta_r,F_r).
\]
这一过程将对数据与环境的初始理解同持续的策略调整联系起来。探索指导在后续轮次中复用，反馈更新生成指导与题型难度配比。

\subsection{数据与环境探索}
任务机会取决于记录之间的关系及其可获取性。例如，比较用药调整前后的检查结果，需要定位调整事件、相关指标和时间窗口；检查次数较多并不意味着这些条件同时成立。MedEvolve 在初始阶段分别探索患者数据和工具环境，得到数据指导 $K_D$ 与环境指导 $K_E$。

\textbf{数据探索。} 探索 Agent 从进化患者集合中读取缓存轨迹，归纳记录的组织方式、时间变化、事件关联及可支持的提问模式。轨迹读取受模型上下文预算约束，裁剪或压缩材料保留覆盖标记。模型不能依据摘要或裁剪材料中缺少某条记录，断言原始病历中不存在相应事实。原始来源保留供后续证据核验。

数据指导以可复用的自然语言规则表达临床模式及其证据要求。例如，比较治疗前后的指标变化，需要对应的治疗记录、时间可定位的检查及可比的数值或描述。观察到的时间先后支持变化分析，但不能单独证明治疗与结局的因果关系。指导不保存患者标识、个体检查值或具体来源编号，具体问题仍由目标患者的记录支持。

\textbf{环境探索。} 探索 Agent 在独立实例中实际调用开放患者范围内的只读工具，识别参数、返回结构、分页及结果裁剪等约束。环境指导明确区分已验证能力、调用失败与未验证能力，并记录定位证据和读取详情的可行方式。工具声明本身不构成能力已经验证的证据。

两类指导在初始阶段形成，随后固定复用。数据指导提供提问模式，环境指导约束证据获取方式；二者的固定部分与后续更新的生成策略分别保存。探索成本按实际调用记录，在整个任务构建流程中摊销。

\subsection{知识引导的任务生成}
对患者 $p$，生成器接收预算内轨迹 $X_p$、探索指导 $(K_D,K_E)$、生成指导 $g_r$ 和两个采样方向。每个方向包含临床题型、自然语言难度要求及其采样权重。题型限定为诊断与解释、检查与风险分层、治疗规划、药物处方和治疗重规划。

生成器通过一次模型调用完成模式选择与任务构建。它先判断当前记录能支持哪些提问，再围绕相应证据形成问题、候选参考答案和来源声明。跨记录结论分别引用相关依据，答案区分记录事实与临床推断，并允许有证据支持的等价方案。生成指导和方向配比共同约束候选选择，不强制模型将每个患者实例化为相同临床模式。

候选批次经过结构、数量、题型与来源检查。每位患者最多输出两道任务，生成不足和批次拒绝均保留在产量与成本记录中，不通过补造事实填满数量。对时间字段缺失或必要记录不足的情境，问题和答案必须明确证据边界。

\textbf{证据核验。} 公共核验从环境重新读取每条引用的原始记录，检查该记录是否支持对应声明，再判断整道任务的证据支持性与清晰度。通过核验的任务进入质量、难度与独立解题评价。核验未通过的任务保留原因，仍可用于生成缺陷的反馈分析；缺少可靠解题评价时，不据此推断解题能力不足。

核验与质量评价分别承担来源一致性检查和任务构建评价。两者均可能受模型判断偏差影响，实验分别报告核验通过率、评价覆盖和质量分布，并通过人工审查分析其一致性。

\subsection{反馈驱动的策略进化}
生成侧的进化对象是策略 $\theta_r=(g_r,w_r)$，解题 Agent 的模型与执行设置在对应实验条件下保持固定。通过核验的任务分别获得四维质量评分、四级推理深度和完成评价；执行轨迹保留工具使用、预算与故障信息。质量、推理要求和解题表现共同进入反馈，低完成率本身不作为任务价值的依据。

\textbf{反馈归因。} 反馈分析按患者组织当前任务、轨迹和评价，归纳事实错误、证据不足、题意歧义及可能的检索或推理困难，再汇总为跨患者发现。工具、环境、模型故障和预算耗尽与临床失败分开记录。高质量任务上的解题失败可提供能力需求的线索，但这一判断仍需结合执行轨迹与评分可靠性。

\textbf{策略更新。} 更新函数 $U$ 依据当前策略和反馈修订生成指导，以及带题型和难度描述的方向权重。例如，证据不足的反馈可转化为选择时间窗口或组织引用的约束；不同方向上的质量与完成表现可影响后续采样配比。权重非负且至少一项为正，策略不保存患者特定答案。

进化患者按轮次划分，每轮生成和评价后执行反馈分析与策略更新。初始探索指导保持固定，轮次结束后冻结生成策略，并在患者独立的评测集合上生成任务。初始与最终策略的控制比较使用同一评测患者集；进化轮次之间患者组成不同，其逐轮指标同时反映策略与样本变化。

\section{实验}
\subsection{研究问题}
实验分别评价生成任务的构建水平与下游学习价值，并通过组件分析解释其来源。

\begin{enumerate}
\item \textbf{质量与推理要求。} 不同方法能稳定产出多少可核验任务？其质量、推理层级和纵向证据结构如何分布？
\item \textbf{下游价值。} 在模型权重固定时，不同任务来源积累的经验能否改善官方医疗任务上的完成表现？
\item \textbf{机制贡献。} 数据探索、环境探索和反馈更新分别如何影响生成结果？
\item \textbf{收益与投入。} 生成策略和解题经验的收益需要多少探索、生成、评价与学习成本？
\end{enumerate}

\subsection{评价指标与统计口径}
\textbf{有效性与质量。} 实际生成量、核验覆盖与核验通过率共同描述有效产出。通过率以具有核验结果的任务为分母；核验缺失、运行故障及生成不足分别报告。质量从事实准确性、临床合理性、证据充分性与题目清晰度四个维度按 1–5 分评分，各维度分别报告均值、分布及不低于 4 分的比例。评分只覆盖核验通过且该评价阶段成功的任务，不解释为全部请求任务的平均质量。

\textbf{推理与证据结构。} 推理深度包含事实查询、单步推理、整合推理和临床决策四级，报告层级分布，高阶推理定义为第 3–4 级。去重来源数、资源类型数与引用记录时间跨度描述证据结构，不直接视为推理难度。时间信息缺失时保留缺失标记。

质量与难度分别由两个模型独立给出整数评分。聚合采用整数中位数，两分数中位数为小数时向下取整；原始评分和理由同时保留。人工一致性与裁判分歧作为补充分析，聚合规则见附录 D。

\textbf{完成表现与成本。} 生成任务的完成率分别以全部生成任务、具有完成评价的任务为分母。运行结束状态与是否完成任务分开解释：评价流程结束不等于解题成功。生成侧成本按模型调用、输入和输出 token 汇总，核验与解题等公共评测成本单列；缺失用量不以零替代。

\textbf{不确定性。} 方法级结果按环境和模型分别汇总，并同时报告患者数和任务数。置信区间以患者为单位重采样，在相同患者集合上比较的方法保留患者配对。实验 2 的初始与最终状态在同一测试题上配对；患者级区间只表示测试样本不确定性，单次训练的区间不代表跨训练运行稳定性。具体规则见附录 D。

\subsection{实验 2：合成任务驱动的 Agent 经验学习}
实验 2 固定模型权重，将不同方法生成的任务用于 Agent 的技能、记忆或策略手册更新。实验条件为任务来源与 Harness 的组合：六种来源分别接入 OpenClaw、Hermes Agent、ACE 和 Reflexion，同一环境共有 24 个学习组。来源比较在同一 Harness 内进行，Harness 比较报告相对其自身初始状态的变化。

\textbf{任务冻结与训练。} 每个来源只纳入核验通过且完成条件为只读的任务，固定数量不超过各来源的最小有效产量。以种子 42 抽样，按任务划分为 70\% 训练集和 30\% 合成测试集，训练数向下取整。PhysicianBench 当前运行配置每来源选取 25 题，训练 17 题、辅助测试 8 题；其他环境的实际数量以冻结清单为准。同一来源在四种 Harness 中共享任务、划分和顺序。

训练期间每题新建解题会话与医疗实例，跨题只保存经验，不继承完整对话。参考答案和证据不进入本题初始解题输入，执行后供评审和经验更新使用。学习组从各 Harness 的统一初始状态出发，完成固定训练轮次后冻结最终经验；选择最终状态，不依据测试成绩选择经验版本。故障与学习未触发单独记录。

当前 PhysicianBench 配置使用 GPT-4o-mini 执行、辅助分析和经验更新，训练一轮、种子 42、一次运行。同一 Harness 内各来源保持模型、训练数量、轮次及原生限制一致。Harness 的实际学习机制、执行限制和经验隔离见附录 E。

\textbf{官方任务上的共同评测。} PhysicianBench 与 MedAgentBench 的官方任务承担主要外部评价。同一环境和 Harness 下，各来源最终经验与统一初始经验在相同官方任务、模型、工具和执行限制下评测。官方题目、参考答案及评分反馈不参与合成任务生成或经验训练。测试关闭经验写入和后台学习，每题使用冻结快照的临时副本、新会话与独立医疗实例。

评分采用各环境的官方原生规则：PhysicianBench 记录任务成功与检查点成绩；MedAgentBench 按锁定任务版本和官方评分逻辑判定完成。官方任务按其原生要求开放工具和文件交付，不沿用合成训练任务的只读限制。两个环境的分数分别报告，实际数据版本、评分资产和任务覆盖见附录 E。

设官方任务集为 $B$，初始与最终经验状态分别为 $h_0$ 与 $h_m$。任务成功率及百分点提升定义为

\[
\begin{aligned}
A(h)&=\frac{1}{|B|}\sum_{i\in B}\mathbf{1}[\operatorname{success}(i,h)],\\
\Delta_m&=100\bigl(A(h_m)-A(h_0)\bigr).
\end{aligned}
\]
主成绩使用计划任务总数为分母，并单列运行与评分故障、有效评分数及覆盖率。初始与最终均获得有效评分的同题配对集合另报提升及区间，不能用配对子集掩盖完整测试覆盖。

\subsection{案例分析}
纵向案例从实际生成任务中选取，串联抽象指导、患者记录、问题、答案与引用证据。展示记录之间的时间关系、哪些结论由多个来源支持，以及哪些事实不足以支持进一步推断。生成侧策略变化案例采用同一患者上的初始与最终策略任务，并保留两者的核验与质量结果。

失败案例按生成缺陷和解题困难分别呈现。证据未支持的声明明确定位到原始记录；核验通过但未完成的任务结合检索轨迹解释困难，不将故障作为临床失败。经验学习案例展示可迁移规则及其在另一测试题上的使用，不以单个成功案例替代总体评测。

\section{讨论与结论}
\subsection{局限性}
\textbf{数据与证据边界。} 自动构建任务受患者记录、时间信息和工具接口限制。轨迹裁剪、缺失记录及不同机构的表达差异影响模式识别；可解析的时间跨度与来源类型也不能完整描述临床信息量。同一数据环境中的患者划分与跨机构、跨数据来源泛化分别解释。

\textbf{模型评价。} 两模型聚合不能消除共同偏差，临床合理性也未必由结构化记录充分判定。质量评分覆盖核验通过任务，复杂任务的证据声明较多，整题核验更容易因其中一条不成立而失败。评价需要同时呈现产量、覆盖、分布和人工审查，不以筛选后的均分代表整个任务生成过程。

\textbf{难度与学习价值。} 高推理层级、较多引用或较长时间跨度描述不同方面的任务要求，不保证任务适合学习。解题成绩受模型、工具与预算共同影响。生成侧的策略更新和解题侧的经验学习是两个不同过程，其效果分别由生成控制比较和共同官方任务评价支持。

\textbf{经验迁移与稳定性。} 合成训练与辅助测试按任务划分，可能共享患者；官方任务也可能与经验训练共享底层记录。患者重叠和答案近重复需要单独报告。当前单种子训练不能说明跨运行稳定性，患者重采样区间只衡量测试样本的不确定性。原生 Harness 的学习触发与调用限制存在差异，跨来源比较优先在同一 Harness 内进行。

\subsection{结论}
MedEvolve 将纵向医疗记录的数据探索、工具环境探索和任务反馈连接到生成策略更新。框架以可复用的临床模式与证据约束指导出题，并分别评价任务可靠性、推理要求、有效产出和成本。实验 1 检验生成结果，实验 2 在固定模型权重下通过共同官方任务评价合成任务的经验学习价值；组件控制、人工审查及成本分析限定这些结论的解释范围。

\section{探索与生成接口}
\subsection{数据探索}
探索工具提供开放患者名单、预算内轨迹及可选压缩摘要。输入材料保留患者标识、原始来源和覆盖标记，输出为不绑定患者的自然语言指导。指导归纳数据组织、时间变化、事件关系、证据引用与可支持的问题，不保留个体临床值或来源编号。

压缩摘要用于定位模式，原始记录用于支持具体事实。记录缺失与材料裁剪分别解释。指导中的时间窗口、记录数量或临床关系属于模型归纳的提问约束，不构成对所有患者统一适用的硬编码医学规则。

\subsection{环境探索}
环境探索在独立实例中访问开放患者的原生只读工具。指导记录已验证参数、返回结构、分页与裁剪行为、典型检索方式，并区分调用失败和未验证能力。环境内的具体患者观察不进入通用指导。

\subsection{任务生成与策略}
任务包含患者标识、临床题型、问题、候选参考答案、来源标识与逐来源事实声明，以及可选时间视角和执行要求。生成调用输入预算内轨迹、两类探索指导、当前生成指导和两个采样方向，输出最多两题。

生成策略由自然语言指导和方向列表组成；方向包含五类临床题型之一、难度描述与非负权重。方向按权重采样，允许同一题型对应不同临床模式；至少一个权重为正。数据与环境指导在策略更新期间固定，更新只修订生成指导和方向列表。

\section{环境、患者与信息访问}
PhysicianBench 的生成患者池为 108 人，MedAgentBench 为官方范围内的 100 人。按种子 42 和既有探索暴露约束冻结进化与评测名单。进化患者分为互不重叠的两轮：PhysicianBench 为 13 与 14 人，MedAgentBench 为 12 与 13 人；评测患者分别为 81 与 75 人。

原始轨迹按记录时间组织，模型输入按预算选取；证据核验读取原始来源，不以输入摘要替代来源。初始探索和任务生成只开放查询工具。解题工具依环境与任务执行要求提供，经验训练的合成任务进一步限定为只读。当前 PhysicianBench 生成配置未启用时间视角属性，问题中的时间限定不等同于服务端隐藏后续记录。

经验学习另按合成任务划分训练与辅助测试，不能与生成侧患者划分混用。冻结清单记录选中题目、患者、训练与测试划分、文件摘要及生成来源。官方任务评测另记录任务版本、患者范围及与经验训练的重叠。

\section{生成方法与预算}
TaskCraft 将患者记录与只读 FHIR 工具映射到原方法的结论抽取、原子任务生成、核验与扩展流程。深度和宽度分支均从原子任务出发，彼此没有先后依赖；两条分支共享生成总预算。原子、深度和宽度候选的实际产量及接纳情况分别记录，以区分扩展机制和最终筛选的影响。医疗适配与原论文完整实验复现分别解释。

Workflow 固定执行定位、生成和内部检查，检查只筛选候选。SingleShot 根据轨迹单次生成最多两题。SelfRefine 在同一患者批次内执行初稿、自反馈和修订，最多三次自评、两次修订，全部通过时提前结束。EnvExplore 先获取环境指导，再用固定初始策略生成任务。各方法共享输出结构和公共评价，内部调用与筛选记录分别保存。

主方法初始探索完成后执行两轮生成侧策略进化，每轮按患者归纳反馈并汇总更新。批次输出的结构或配额校验失败保留为生成失败。反馈和更新调用失败不视为进化成功。输入裁剪、实际调用与预算耗尽分别记录。

模型路由、上下文上限、输出限制和工具预算以冻结运行配置为准。同一比较中报告各方法预算与实际用量；相同出题数量不表述为严格相同 token 预算。探索和更新计入主方法总成本，公共评价成本单列，历史复用调用按原始记录去重计数。

推理深度依据问题要求及证据结构标注：第 1 级直接读取事实，第 2 级结合记录与临床知识完成单步判断，第 3 级跨记录比较或整合信息，第 4 级综合证据权衡风险收益并提出方案。临床题型与推理层级分别记录，不把治疗规划题自动判为最高层级。

对任务 $i$、质量维度 $d$，两个模型的原始评分为 $s_{i,d}^{(1)}$ 与 $s_{i,d}^{(2)}$，最终评分为

\[
s_{i,d}=\left\lfloor\operatorname{median}\left(s_{i,d}^{(1)},s_{i,d}^{(2)}\right)\right\rfloor.
\]
难度采用同样聚合规则，保留两个原始层级与理由。正式协议要求两份有效输出，不以单个成功裁判替代缺失评价。质量评分材料包含题目、参考答案、证据、轨迹与核验结果；难度评分依据任务要求和自动复杂度。原始评分用于分歧分析。

\subsection{证据结构与比率}
对引用来源去重得到 $S_i$，证据数量为 $|S_i|$，资源类型数由可识别类型前缀去重得到。引用记录中可解析的时间集合为 $T_i$，其跨度为

\[
\Delta_i=\frac{\max T_i-\min T_i}{1\text{ 天}}.
\]
无可解析时间时记缺失，只有一个可解析时间时为零。报告时间可解析任务数，跨度分布和中位数仅使用非缺失值。

\subsection{不确定性与人工审查}
