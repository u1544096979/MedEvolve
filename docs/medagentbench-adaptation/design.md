# MedAgentBench 环境适配设计

## 适配目标与边界

MedEvolve 在 MedAgentBench 官方患者数据和原生交互规则上生成新任务，并执行公共核验、解题、反馈与策略自进化。患者数据、接口列表、请求格式与执行语义以官方源码为依据。

原生行为基准为 MedAgentBench 提交 `99260117137b09f04837a8c18d18a1107efa55ae`：

- [环境安装与参考判定函数获取](https://github.com/stanfordmlgroup/MedAgentBench/blob/99260117137b09f04837a8c18d18a1107efa55ae/README.md)
- [任务执行器](https://github.com/stanfordmlgroup/MedAgentBench/blob/99260117137b09f04837a8c18d18a1107efa55ae/src/server/tasks/medagentbench/__init__.py)
- [原生接口声明](https://github.com/stanfordmlgroup/MedAgentBench/blob/99260117137b09f04837a8c18d18a1107efa55ae/data/medagentbench/funcs_v1.json)
- [官方任务配置](https://github.com/stanfordmlgroup/MedAgentBench/blob/99260117137b09f04837a8c18d18a1107efa55ae/configs/tasks/medagentbench.yaml)
- [官方结果判定入口](https://github.com/stanfordmlgroup/MedAgentBench/blob/99260117137b09f04837a8c18d18a1107efa55ae/src/server/tasks/medagentbench/eval.py)

环境适配属于公共层，各方法在同一环境内共享适配与评测口径。MedEvolve 保留初始数据探索、初始环境探索、单患者单次 LLM 生成、公共评测、本轮反馈和策略更新。初始探索指导在实验内固定，策略更新不训练模型参数。

公共数据结构和方法入口保持现有约定。原生交互的运行分派属于环境与公共运行层，不在主方法中按环境名称编写算法分支。PhysicianBench 的工具执行方式保持现有行为。

## 原生执行规则

### 实例与数据

采用官方镜像 `jyxsu6/medagentbench`，首次获取后记录镜像摘要，实验固定使用该摘要。镜像提供 FHIR 服务，原生地址路径为 `/fhir/`。

复用现有本机 Docker 管理服务，扩展环境分派；每次创建独立实例、返回实例地址并在使用后释放。轨迹整理、环境探索、任务核验和解题从相同种子数据开始，不共享可写存储。实验串行执行，单容器采用现有 4 GB 内存上限；启动能否满足该上限以实际验证为准。

### 模型交互

环境探索与解题获得官方接口声明，通过文本动作交互，每轮最多一个动作：

- `GET URL`：按官方执行器规则发送请求，返回查询结果或错误。
- `POST URL`，后接 JSON：按官方执行器规则解析请求并返回接受结果。
- `FINISH([...])`：结束原生交互，保留提交的答案列表。

接口列表保持官方查询和提交能力，不把 PhysicianBench 的接口列表作为 MedAgentBench 的可用工具。环境探索和解题使用同一原生动作执行器。

原生执行循环接入公共模型预算、工具预算和运行记录。GET、POST 分别作为工具动作计数，并输出公共核验可读取的 `tool_start`、`tool_output` 记录；FINISH 作为终止动作。原始模型输出、请求、结果与错误保留在 trace 中。公共运行结果继续采用 `RunResult`；解题 FINISH 的答案列表按内容序列化到 `SolverAnswer.answer`，不增加模型调用改写答案。环境探索的最终内容映射到 `EnvironmentExploration.guidance`。

公共访问边界继续限制实验开放的患者范围，记录由该边界拒绝的请求。身份定位查询只能返回开放患者的匹配结果；这属于实验访问限制，不作为官方行为的复现结论。

### POST 的语义

指定版本的官方执行器在 POST 分支解析 JSON 后返回成功提示，没有向 FHIR 服务发送写入请求。适配保留此行为，不增加实际数据库写入。

操作记录分别保存原始提交、解析结果和环境返回；状态读取保存实际数据库资源。接受提交与数据库变化是不同事实。既有资源不能被当作本次提交创建的结果。

## 患者数据整理

适配层从官方 FHIR 数据整理单患者材料，输出现有 `PatientTrajectory`：

- `patient_id` 使用原生患者资源 ID；MRN 等标识保留在患者原始记录中，不与资源 ID 混用。
- `text` 按临床事件时间排列记录，保留就诊引用、日期、数值、单位及关键原始字段。
- `sources` 以 `ResourceType/id` 关联完整原始记录；公共核验可按相同来源读取原始数据。

排序不使用数据库更新时间代替临床时间。无日期记录明确标记为无日期，不推断时间；就诊和其他资源引用保留原值，不把相邻记录合并成未经记载的病程事实。

整理层不生成病程总结、不推断疗效或临床因果，也不预先挑选出题模式。公共数据读取可取得整理与核验必需的原始记录，但不因此扩大解题 Agent 的原生接口能力。

数据探索继续通过 `list_patients` 和 `read_trajectory` 自由读取进化患者材料，归纳数据组织、记录关联和出题机会。其算法与输出结构不因 MedAgentBench 改变。独立评测患者不进入探索和策略学习。

## 任务背景与方法接入

官方任务将题意和必要背景分别保存在 `instruction` 与 `context`。当前公共任务结构仅有 `instruction`，因此新任务将必要背景显式写入题目正文，不新增公共 context 字段。

相对时间题必须给出明确的当前时间；依赖特定编码或剂量规则的题必须提供必要编码和规则。患者事实来自原始记录并列出证据；任务设定和给定规则在题目中明确标识，不冒充患者记录，也不使用未说明来源的临床规则生成唯一答案。

任务要求与原生能力对应：

- 查询与分析题要求从原生查询结果回答问题。
- 提交题明确要求提交何种请求及其条件，不声称原生 POST 会持久化资源。
- 要求实际创建或修改数据库资源的题不属于本版本适配的可完成任务。

单次生成仍接收患者轨迹、两份初始指导、当前策略和两个生成方向，返回题目、候选参考答案和证据。环境探索指导描述实际观察到的原生能力与限制；生成和反馈依据这些指导工作，不增加专门的 MedAgentBench 生成算法。

`decision_point` 保持为 null。题目给定当前时间用于解释时间范围，不代表环境已经过滤未来记录。

## 公共核验

继续使用公共证据核验、整体答案核验、四维质量评价和完成评价。证据按来源读取原始数据；解题输入不包含参考答案、证据列表或缓存轨迹。

完成评价根据题目明确要求和原生执行证据判断：查询题比较回答与证据；提交题核对实际 POST 动作及提交内容是否满足题目；要求数据库变化的任务必须有实际状态证据。仅凭环境成功提示不能认定数据库写入成立。

`observed_state` 在原有 JSON 容器中保留实际资源快照与原生操作语义说明，提交内容保存在 solver trace。公共判定规则对同一环境内所有方法一致，不为 MedEvolve 单独放宽完成条件。

官方 `refsol.py` 按固定任务类型判定原题，不能替代新任务的公共核验。官方原题验证分别报告原生交互是否一致与官方判定是否通过；只有取得对应参考函数并实际运行后才能报告后者。

模型、工具或环境故障保留独立失败类别，不计为任务难度提升。反馈使用真实核验和执行结果，策略更新保留现有结构。

## 验收标准

1. **原生交互**：串行运行一条官方查询任务和一条官方提交任务，比较输入、动作、响应与指定版本执行器；验证 FINISH 终止和答案映射。POST 接受后回查数据库，确认结果符合原生执行语义。
2. **数据与实例**：核对患者标识、时间、就诊引用和来源回查；串行创建与释放实例，确认新实例恢复种子数据，开放范围以外的患者不可访问。释放后没有遗留受管实例。
3. **公共核验**：使用真实记录验证正确与错误证据；对提交成功、内容错误和未提交三种情况核对完成判定，成功提示不能覆盖错误请求内容或证明数据库写入。
4. **新题小样本**：验证一次生成、指定题型、背景完整性、候选答案与证据一致性，以及解题输入隔离；保留无效题和运行失败的实际结果。
5. **两轮闭环**：以已授权的 DeepSeek V4.1 Flash 串行执行两轮反馈与策略更新，再在独立患者上生成评测任务；报告生成量、有效量、完成量、失败类别、模型调用和 token 用量，不以小样本宣称进化收益。
