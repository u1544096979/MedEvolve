# 环境工具可靠性

## 1. 工具返回

PhysicianBench 的工具返回使用合法 JSON。`environment.tool_result_limit` 控制每次返回的字符上限，包含 JSON 结构、记录和裁剪标记；默认值保持 10000，现有环境探索配置使用 5000。字符上限不代表 token 上限，由实验配置根据模型上下文调整。

工具执行与患者访问检查完成后，在返回数据结构上选择完整记录，再序列化。未超限的结果保持现有结构和内容。超限的查询结果保留原顺序中的完整记录前缀，不删除记录内部字段、不截断字符串，也不在 JSON 末尾追加文本。

裁剪后的查询结果保留 `entries` 和能够容纳的原有结果信息，并附加 `truncation` 对象：

- `truncated`：是否因返回长度上限裁剪。
- `total_records`：本次工具实际取得的记录数，不替代服务返回的 `total`。
- `returned_records`：本次交付的完整记录数。
- `message`：提示结果未完整交付，需要缩小查询范围。

如果第一条记录已经超限，返回空记录列表和裁剪信息，明确提示单条记录超过上限。非记录列表结果超限时，返回结构化超限提示，不返回部分资源；写入响应超限时，仍明确保留操作成功的事实，不能提示重新执行写入。返回长度限制只约束交付内容，不改变工具执行结果。

配置值必须足以容纳最小结构化提示；不能容纳时，在工具调用前报配置错误。最终返回长度必须不超过配置上限。序列化可用于测量长度，但不能对序列化字符串硬切。

返回限制沿用 PhysicianBench 现有绑定入口，不扩展到 MedAgentBench 的原生文本动作通道，不新增分页接口。

## 2. 环境探索提示词

共享环境探索提示词明确以下规则：

1. 交付指导前必须实际调用环境工具，不得仅根据函数清单声称能力已验证。
2. 相同工具与相同参数的查询不重复执行；调整筛选范围、修正错误参数、读取已有下一页和写入后的必要回读允许执行。
3. 返回被裁剪时缩小查询范围，不通过重复原查询获取缺失内容。
4. 已取得足够信息说明工具参数、返回结构、能力和限制后立即交付；不要求逐个验证全部工具或全部患者。
5. 指导区分已验证能力、调用失败和未验证能力；提交被接受不等于数据库持久化成功。

保持现有输出接口和原生 FINISH 格式，保持轮次与工具调用预算。探索约束只通过提示词表达，不增加去重执行器、调用次数检查、自动重试或指导验证模型。

## 3. 参数说明与错误恢复

MedAgentBench 的函数清单按当前适配服务的实际参数范围校准。参数表和描述必须一致；Condition 的描述不能声称支持未列明、实际不支持的 `status` 筛选。其他 GET 声明同步检查相同矛盾，未经验证的筛选条件不能补入清单。未知参数不得静默忽略，客户端不自动修改模型请求。

原生 GET 返回 HTTP 400 时，按状态码将其记录为可恢复的工具错误，不解析响应体来判定参数问题；反馈状态码、服务错误信息和修正参数的提示。模型可在现有预算内修正并重新请求。该错误保留在执行记录中，但不设置运行时的永久环境失败标记；后续成功执行并提交合法 FINISH 时，可以正常完成并进入现有状态回读与完成评价。

待修正参数错误的失败判定只适用于解题运行：探索运行的目标是探测环境能力与参数边界，在如实交付该限制后即告完成，一次被服务拒绝的参数探测不使探索运行失败。

HTTP 401、403、404 与 5xx、连接失败、超时、认证故障和患者访问边界异常继续按环境故障处理。不能通过清除环境失败标记掩盖这些故障，也不能将所有 HTTP 4xx 一律认定为可恢复参数错误。

恢复只表示执行流程可以继续，题目是否完成仍由最终答案、操作记录和环境状态按现有规则判定。没有成功恢复或没有合法 FINISH 的运行不能直接判为完成。

## 4. 验证与边界

验证使用现有环境与运行时测试入口，重点覆盖以下行为：

1. 未超限结果保持完整；超限、多条记录、单条超大记录和包含中文或转义字符的返回均可解析为 JSON，且实际字符长度不超过不同配置上限。
2. 保留记录与原始记录完全一致，计数和裁剪提示准确；无法容纳最小提示的配置在调用前拒绝，写入响应超限不导致重复写入提示。
3. 环境探索调用共享提示词，包含真实调用、查询去重、修正重试和及时交付规则；预算和输出接口保持兼容。
4. 参数错误的 GET 400 后成功重试并 FINISH 可以完成，错误仍在记录中；真实环境故障保持失败，参数表与描述一致。
5. 恢复后的运行继续执行现有完成评价；患者访问边界与原生提交语义保持有效。

长病历的出题输入、轨迹压缩、病历字段精简和生成方法调整不属于本设计范围。
