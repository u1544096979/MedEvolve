# TaskCraft 医疗适配修复设计

## 1. 生成预算与比较口径

MedEvolve、TaskCraft、Workflow、SingleShot、SelfRefine（配置键 `selfgen`）、EnvExplore 在同一环境内采用统一的每患者生成预算上限：`runtime.budgets.generator.max_model_turns=800`、`max_tool_calls=800`。

预算是上限，各方法保留自身生成流程、重试次数与停止规则，不为消耗额度追加调用。TaskCraft 保留作者源码提交 `1e405e0b02c4738654e2d885b16677b46c9fe969` 的原子生成、内置核验、深度扩展与宽度扩展机制及现有参数。实际调用、工具使用与 token 消耗全部计入生成成本。

统一口径覆盖正式对比配置、基础配置与配置生成脚本；机制验收配置保持相同生成上限。探索、策略更新和公共评测角色的预算保持各自口径。既有运行产物中的配置与结果作为历史记录保留，不改写。

800/800 是统一外部上限，不保证每名患者都能完成所有阶段。质量、题数和成本按实际运行结果报告。

## 2. 预算耗尽与候选交付

TaskCraft 达到累计预算上限后停止发起调用，并从已完成内置核验的候选池中按现有题型配额与固定种子选择最多两题。未完成核验的原子题与未完成扩展检查的题目不进入输出。

有合格候选时，`RunResult.status` 保留 `budget_exhausted`，`output` 携带有效 `TaskBatch`，`error` 说明耗尽原因，`trace` 与 `usage` 保留实际阶段记录和全部成本。没有合格候选时保持 `budget_exhausted` 与空输出。

公共生成结果汇总、`validate_task_batch` 与实验入口的生成批次解析支持预算耗尽后的有效输出：仍执行完整字段与题型约束检查，通过检查的题目进入公共评测，生成尝试记录仍显示预算耗尽及实际产出数量。该规则依据生成结果状态与数据适用，不按方法名放宽评测标准；其他方法的生成算法不改变。

预算耗尽与实际超预算分别处理。实际模型调用或工具使用超过配置上限时，实验入口继续拒绝输出。失败状态不携带可评测批次，非法批次不得因为预算耗尽而绕过校验。公共的探索、反馈等非生成调用保持既有成功解析规则。

## 3. FHIR-AgentBench 工具适配

TaskCraft 生成阶段支持 FHIR-AgentBench 的只读工具 `get_resources_by_resource_id` 与 `get_resources_by_patient_fhir_id`，沿用环境提供的工具参数、描述、资源范围与患者访问约束。

工具接入使用现有函数工具检索 Agent 路径。检索提示与参数指导与这两个工具的真实声明一致，不要求不存在的参数。PhysicianBench 的只读函数工具与 MedAgentBench 的 GET/FINISH 原生协议保持各自调用语义。生成阶段不开放写入工具。

## 4. 证据与核验规则

候选证据以 `(source_id, statement)` 为去重键。同一记录支持多个不同事实时，各条事实均保留；同一来源与同一事实的重复引用仅保留一次。宽度合并与深度辅助关系的证据汇总采用该规则，保持原始来源标识与事实文本。

TaskCraft 原子题接纳条件沿用作者源码：内置核验没有返回错误即继续接纳，不额外要求工具 Agent 得分大于零。内置接纳不替代公共证据核验与质量评价。参考答案、深度与宽度的算法检查条件及最终选题规则保持现有方法定义。

## 5. 验收

离线验收覆盖以下行为：

1. 六种方法的正式生成配置与生成脚本均采用 800/800 上限，各方法自身停止规则不改变。
2. TaskCraft 耗尽预算后保留已有合格候选；无候选时不输出题目，未核验候选不进入输出。
3. 预算耗尽批次通过公共校验后进入评测，耗尽状态与成本保留；非法批次、失败结果及实际超预算输出被拒绝。
4. 三环境生成工具绑定符合对应协议，FHIR-AgentBench 两个检索工具可调用，患者范围与只读边界保持有效。
5. 宽度与深度证据保留同一来源的不同事实并去除完全重复项，原子题接纳条件仍与作者源码一致。

真实模型验收需要单独获得用户授权后运行；执行时检查三环境的真实工具调用、候选证据和公共评测接续，记录实际产出与成本，不以离线测试替代真实机制结果。
