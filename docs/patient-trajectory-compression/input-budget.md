# 患者轨迹输入预算

## 模型输入预算

六种生成方法共用输入预算管理。上下文上限减去输出额度、提示词、输出 schema、工具声明与消息余量后，剩余空间分配给患者记录及阶段材料。GPT-4o-mini 使用匹配的分词器；不支持的模型使用 UTF-8 字节数作为保守估计。配置的 `context_window` 和 `max_output_tokens` 优先，兼容未声明上限的旧配置时沿用 128,000 / 16,384 的预算。新生成的对比配置显式声明这两个值。

实验入口使用统一预留生成患者材料。每次模型请求再按实际提示词与阶段材料检查，避免候选题、反馈或历史记录挤占病历空间。输出上限同时传给模型接口。

## 病历选取规则

短轨迹保留全部材料。超预算时沿用公共记录优先级和同类近期记录优先规则，选取完整原始记录，正文与来源同步。选取规则不依赖方法和出题方向。候选题或焦点已引用的来源保留，避免后续审查失去事实依据。

材料带有部分轨迹标记；缺失记录不能解释为患者没有对应病史。单条必需记录、无法定位来源的正文或固定阶段材料已经超出预算时，返回明确错误，不切断临床事实或发送已知超限请求。单个患者材料错误记录在该患者的生成结果中，不中断其他患者。

原始患者缓存保持完整，证据核验仍读取完整轨迹与原始来源。

## 六方法接入

| 方法 | 输入预算 |
|---|---|
| SingleShot | 病历与题型材料按完整请求预算选取 |
| EnvExplore | 额外计入环境指导与策略 |
| MedEvolve | 额外计入数据指导、环境指导和策略；反馈中的多患者轨迹共同分配预算 |
| SelfGen | 每次审查和修订计入候选题与反馈，保留候选引用的来源 |
| Workflow | 定位和生成按阶段预算选取；核查保留候选引用的原始记录 |
| TaskCraft | 原子阶段保留分块；搜索与反思保留任务、近期完整步骤及当前规划，限制历史总预算 |

SDK 与原生工具循环在请求前计入历史。过长历史按完整交互删除旧步骤，保留当前请求及其工具结果配对。历史缩减明确标记，完整调用记录保留在 trace。必需的最新交互无法容纳时返回上下文预算错误。预算耗尽后的收尾请求也执行相同检查。

## 超限处理与验证

每次请求记录输入预算、计数方式及材料缩减信息。模型接口发送的输出额度与本地预留一致。本地无法容纳的请求在调用前失败，未发起调用不计模型轮次。

验证覆盖中英文及 JSON 转义、完整记录与来源同步、已引用来源保留、单条超大记录、来源无法匹配、固定提示词超限、多阶段材料增长、工具调用配对与历史增长、六方法长轨迹生成，以及原始核验材料完整性。默认验证使用本地假接口，不调用付费模型。
