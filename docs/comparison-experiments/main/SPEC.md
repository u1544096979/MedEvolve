# MedEvolve 主方法规范

## 方法流程

患者轨迹整理 → 初始数据探索与环境探索 → 单患者出题 → 公共评测 → 本轮反馈 → 策略更新。两种初始探索分别产生不绑定患者的抽象指导；进化更新出题指导和题型难度配比。

## 生成任务和参考答案

保留每个患者一次 LLM 调用，根据轨迹、两种指导、当前策略和两个生成方向返回 TaskBatch。题目、候选参考答案和证据一起生成，不额外增加自由探索 Agent。

生成时先选定真实记录中的事实依据，再围绕这些事实组织题目、答案和引用。每条 statement 只陈述该 source_id 记录实际支持的事实；跨记录结论分别引用其依据，不把一个资源 ID 绑定到另一条记录的值或药物。

reference_answer 是候选参考答案。事实查询给出对应数值、时间及单位；临床判断给出记录支持的判断与理由，区分患者事实与推断，不能编造耐受性或把后续真实治疗当成唯一正确方案。允许材料不足时少出题。

## 任务和答案核验

公共层按 source_id 从环境读取原始记录，每次一次 LLM 调用比较一条证据声明与一条记录。引用全部通过后，另一次调用判断题目是否明确、答案是否回应题目以及依据是否充分。明确不成立的任务停止进入解题；环境或模型故障单独记录。

核验结果与质量评价进入反馈。固定解题 Agent 只收到题目、患者和工具；完成评价允许合理等价答案，写入要求用实际操作与环境状态核对。该流程提供模型核验结果，不提供人工金标准。

## 当前边界

不增加答案 DSL、单独标注系统或自动答案修复循环。环境探索须区分工具声明与实际验证能力。决策点保留可选，当前 PhysicianBench 实验使用 null。
