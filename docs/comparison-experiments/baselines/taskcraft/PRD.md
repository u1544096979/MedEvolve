# TaskCraft 实施任务

## 归属

负责 methods/taskcraft/ 及对应方法测试。公共配置与实验分派由公共实验 section 集成，不能修改其他方法。

## 实施步骤

1. 对照 SPEC.md 中的固定源码提交，整理原子、深度、宽度、内置核验的实际调用关系与提示词，列明医疗工具映射和不能直接复用的部分。
2. 接入患者轨迹、医疗工具与配置模型，优先复用核心函数；适配确需移植的阶段时保留源码逻辑与许可证归属。
3. 实现原子生成和内置过滤，再实现深度及宽度扩展；保存父题、扩展结果和失败尝试，累计所有调用成本。
4. 将阶段结果映射为 TaskBatch，并为每条患者事实提供实际 source_id；补齐引用不能修改原算法答案来迎合公共评测。
5. 使用原子、深度、宽度各一个小样本验证对应机制，再通过公共评测入口联调。

## 最小验收

扩展确实依赖父任务，内置核验实际执行；输出证据属于当前患者；方法不读取主方法探索指导；算法失败不以 SingleShot 替代。报告实际调用量和源码适配差异，不以有效题数不足触发无限补题。

## 交付

实现提交、源码到模块的对应说明、可运行配置需求、小样本运行记录与公共评测结果。若医疗环境无法保持某阶段的核心机制，先提交具体不兼容点，调整方法定义后再实现。
