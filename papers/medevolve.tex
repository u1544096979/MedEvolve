\begin{abstract}

在长程医疗轨迹上生成合适的医疗任务并不容易。患者信息分散在多次就诊和不同类型的记录中，临床事件之间存在复杂的时间关系，有意义的提问还需要充分的证据支持和可核验的答案。任务生成需要理解患者轨迹、识别值得提问的临床情境，并协调任务质量与难度。本文提出 MedEvolve，一个数据探索驱动的医疗任务自进化框架。框架结合长程轨迹的数据探索与工具交互的环境探索，将临床事件关联和环境使用知识转化为出题指导，随后通过任务核验、独立解题与反馈分析，更新出题策略。研究围绕数据探索驱动出题和反馈驱动的策略进化两项机制展开，以四维质量评分、四级推理深度、自动复杂度、完成表现与调用成本评价生成任务。

实验结果与主要发现待补充。

\end{abstract}

\section{引言}


\subsection{研究背景与动机}


基于大语言模型的医疗 Agent 可以通过工具访问电子病历，检索患者信息并完成医疗问答。面向纵向病历的任务要求 Agent 在多次就诊、不同资源类型与分散记录之间组织证据，并理解临床事件的时间关系。因此，这类任务的构建不仅涉及自然语言问题的生成，还需要明确问题所依赖的患者信息、证据范围与答案依据。

人工编写任务能够针对具体场景设计问题，但逐一梳理病历、选择提问内容和核验答案需要投入较多工作。随着数据环境和患者轨迹变化，任务集也需要持续更新。自动任务构建由此提出一个研究问题：如何从已有医疗数据中发现值得提问的临床过程，生成有证据支撑的任务，并使任务分布随解题能力的变化而调整？

\subsection{医疗任务构建的挑战}


这一问题包含三个相互关联的挑战。首先，任务机会的发现需要理解数据本身。不同医疗环境在资源类型、时间字段、记录密度和临床信息表达方式上存在差异；能够形成有效任务的事件链，需要结合具体患者轨迹识别。例如，围绕用药变化提出问题，需要判断相关记录是否包含足够的时间信息与临床证据。仅确定题型或生成问题文本，尚不足以保证所需证据存在于数据中。

其次，任务需要具有明确的证据依据与可核验的答案。问题文本、可访问记录和参考答案应当相互对应，避免生成缺少支持或含义不明确的问题。对于涉及特定时间视角的任务，还需要明确可用信息的范围，区分作答时能够获取的证据与评估侧用于核验的后续记录。

最后，任务生成策略需要响应解题反馈。通过核验的任务仍可能集中于解题 Agent 已掌握的能力，也可能因证据检索、信息整合或时间推理要求过高而难以完成。解题失败本身不能直接说明任务具有学习价值，还需要区分任务缺陷与解题能力不足。如何利用核验结果和失败归因，调整后续生成指导与任务配比，是持续改进任务生成的关键。

\subsection{核心贡献}


针对上述挑战，我们提出 MedEvolve，一个数据探索驱动的医疗任务自进化框架。框架将对长程轨迹的理解与对工具环境的验证结合，归纳可跨患者复用的生成指导，并通过任务质量、推理深度与解题反馈持续改进生成策略。

本文的核心贡献体现在方法创新与学习机制两个层面：

\begin{enumerate}
\item \textbf{数据-环境双探索机制。} 患者轨迹的时间跨度可达数年，记录分散在多次就诊和不同资源类型中，临床事件之间存在复杂的因果和时序依赖。任务机会的识别不能仅依赖环境交互模式或原子任务扩展，而需要结合对长程数据本身的理解。MedEvolve 通过数据探索归纳临床事件关联（如"用药调整与指标改善"需要哪些记录、多长时间跨度），通过环境探索验证这些信息的可获取性（工具能否检索、如何组织调用），将两类知识联合建模为任务生成指导。

\item \textbf{反馈驱动的策略进化机制。} 解题失败本身不能直接说明任务具有学习价值——任务可能因证据不足而无法完成，也可能对解题 Agent 要求过高。MedEvolve 设计独立的质量评价、推理深度标注与完成表现分析，区分任务缺陷与能力不足，并将反馈转化为生成指导的更新与题型难度配比的调整。这使框架能够持续改进任务构建方式，而不是简单积累未通过的题目。

\end{enumerate}

\section{相关工作与问题定义}


\subsection{相关工作}


\textbf{医疗 Agent 与交互式评测。} MedAgentBench 将医疗任务置于可交互的电子病历环境中，评估 Agent 通过工具访问患者记录并执行临床相关操作的能力。PhysicianBench 进一步关注真实病历中的长程复合工作流，通过结构化检查点核验任务执行。这些工作为研究医疗工具使用与纵向信息整合提供了环境和评估基础。MedEvolve 关注如何利用环境中的患者轨迹构建任务，并通过反馈持续改进任务生成策略。\href{https://arxiv.org/abs/2501.14654}{MedAgentBench}，\href{https://arxiv.org/abs/2605.02240}{PhysicianBench}。

\textbf{自动任务构建与环境探索。} TaskCraft 从原子任务出发，通过深度扩展和宽度扩展构建具有多步检索与组合要求的 Agent 任务，并结合核验获得任务及执行轨迹。CuES 通过好奇心驱动的环境探索，将交互模式抽象为任务，并结合指导与质量控制生成可执行任务。这些研究说明，任务结构可以从数据关系或环境交互中获得。MedEvolve 在长程医疗轨迹中结合数据探索与环境探索，将对临床记录、事件关联和工具使用方式的理解转化为出题知识，并以任务反馈更新生成策略。\href{https://arxiv.org/abs/2506.10055}{TaskCraft}，\href{https://arxiv.org/abs/2512.01311}{CuES}。

\textbf{反馈驱动的 Agent 改进。} Reflexion 将任务反馈转化为语言反思并保存在记忆中，指导后续尝试。AgentEvolver 将自主出题、经验引导和贡献归因结合到 Agent 学习框架中，连接任务生成与能力改进。MedEvolve 将反馈用于医疗任务生成侧：核验与解题结果帮助识别任务缺陷及能力需求，并为后续探索和出题策略更新提供依据。本文通过任务质量、推理深度、完成表现与成本评价这一过程。\href{https://arxiv.org/abs/2303.11366}{Reflexion}，\href{https://arxiv.org/abs/2511.10395}{AgentEvolver}。

医疗任务的特殊性在于：患者轨迹跨越数月到数年，一个有意义的提问可能要求理解"用药调整与指标改善"这类跨时间、跨记录类型的临床关系。仅从环境交互模式（如CuES的好奇心驱动探索）难以捕捉这些长程依赖，原子任务扩展（如TaskCraft）也无法解决从海量分散记录中识别值得提问的临床过程。MedEvolve 通过数据探索归纳这些领域知识，再结合环境探索验证可获取性，最后以反馈区分任务质量缺陷与能力不足，持续改进生成策略。

\subsection{问题定义}


给定一个通过工具接口提供长程医疗轨迹数据的可交互环境、固定的解题 Agent 和生成预算，我们研究如何自动构建可核验的医疗任务，并迭代改进任务生成策略。患者轨迹包含随时间积累的就诊、检查、用药及其他临床记录，环境接口提供记录检索与详情读取等操作。任务生成需要同时确定提问内容、允许访问的数据范围以及参考答案依据。

将一个任务记为 $\tau=(p,q,a,E)$，其中 $p$ 为患者，$q$ 为自然语言问题，$a$ 为候选参考答案，$E$ 为支持问题与答案的证据集合。解题 Agent 接收问题与患者上下文，通过环境工具获取作答所需信息；参考答案和证据标注保留在评估侧。

生成策略 $\theta=(g,w)$ 包含生成指导 $g$ 与题型难度配比 $w$。在固定评估流程与解题配置下，我们研究探索所得知识与任务反馈如何改善生成质量，并改变任务的推理要求和证据结构。任务质量、推理深度与解题完成表现分别评价，避免将解题失败直接视为任务价值。

\subsection{任务与评估约束}


策略进化与独立评测使用互不重叠的患者集合。同一患者的记录不跨集合，独立评测结果不参与策略更新。各环境的患者规模与抽样规则在实验设置中报告。

任务依据环境中可访问的患者记录构建。涉及临床判断时，参考答案需要区分记录事实与合理推断，并允许证据支持的等价方案。实际发生的后续治疗可以提供背景，但不能直接构成唯一正确的临床方案。环境支持具有特定时间视角的任务，其信息访问范围随任务定义确定。

盲测不向解题 Agent 暴露参考答案或证据标注。不同方法与进化轮次使用一致的核验规则、评分标准和解题配置，环境或模型故障单独记录。

\section{方法}


\subsection{整体思路}


长程医疗轨迹中的记录数量与类型并不能直接决定值得提出什么问题。任务生成既需要识别临床事件之间的联系，也需要理解这些信息如何在交互环境中获得。MedEvolve 将这两类理解转化为生成指导，再利用任务反馈调整指导内容与任务分布。

设数据探索与环境探索所得知识分别为 $K_D$ 与 $K_E$，第 $r$ 轮生成策略为 $\theta_r$。对患者轨迹 $X_p$，任务生成可表示为

\begin{equation}
\mathcal{T}_{p,r}=G(X_p,K_D,K_E;\theta_r).
\end{equation}


初始探索提供跨患者的知识基础，具体任务仍由当前患者的真实记录支持。每轮任务经过核验、质量与难度评价以及独立解题，形成反馈 $F_r$，随后更新策略

\begin{equation}
\theta_{r+1}=U(\theta_r,F_r).
\end{equation}


这一过程将对数据与环境的初始理解同持续的策略调整联系起来。探索指导在后续轮次中复用，反馈更新生成指导与题型难度配比。

\subsection{数据与环境探索}


长程医疗轨迹中的记录数量并不能直接决定值得提出什么问题。考虑两个糖尿病患者：患者A在6个月内有12次HbA1c检查，患者B只有2次。乍看之下，患者A的数据更丰富。但如果患者B的两次检查恰好分布在用药方案调整的前后3个月，且记录中包含调整依据与用药详情，那么患者B更适合构建"用药调整后指标改善"这类任务——这个任务需要理解用药变化与检查时序的关联，而不是简单统计检查频率。

任务机会的识别需要两类理解。第一，临床事件之间存在哪些值得提问的关系？用药调整、指标变化、诊断确认、治疗方案选择，这些过程在电子病历中如何表现，需要哪些记录、多长时间跨度、什么样的时序约束？第二，这些信息能否通过环境工具获取？工具声明可能支持按时间检索，但实际能力可能要求同时提供起止日期；一个关联查询在接口文档中存在，但返回结果可能需要手动展开引用。

MedEvolve 通过数据探索和环境探索分别回答这两个问题，并将所得知识转化为可跨患者复用的生成指导。

\textbf{数据探索归纳临床事件关联。} 探索从5-10个代表性患者的长程轨迹出发，每个轨迹长度在6个月以上，覆盖不同疾病类型与记录密度。探索Agent读取患者的完整记录，识别临床事件之间的关联模式——哪些指标出现了趋势变化，用药调整与检查结果之间是否存在时序依赖，哪些诊断需要多次记录共同确认。

这些观察随后归纳为提问模式与数据约束。例如，"用药调整与指标改善"模式要求至少两条MedicationRequest记录（用药成分或剂量有变化）、至少两条相关Observation记录（时间分布在用药调整前后）、时间跨度不少于1个月。"诊断确认"模式则要求多次同类型检查、数值均超过阈值、Condition的确诊时间晚于首次异常检查。

数据指导 $K_D$ 将这些模式与约束记录下来，每条指导包含临床关系描述、最低数据要求和可提问方向。这些指导不绑定具体患者，可以在后续生成中用于判断新患者轨迹是否支持该类任务。附录A.1给出数据探索的提示设计与输出示例。

\textbf{环境探索验证证据可获取性。} 数据探索识别的模式还需要在环境中实际可行。环境探索通过工具交互理解检索能力、返回结构与使用限制。探索Agent在独立环境实例中调用工具，验证按时间范围检索、按类型筛选、关联资源展开等操作的实际行为，并识别工具声明与观察到的能力之间的差异。

例如，search\_observations工具可能声称支持按类型和时间范围检索，但实际使用发现date\_from和date\_to必须同时提供，不支持同时查询多个type，且单次返回最多100条记录。这些限制影响任务构建：如果一个问题需要跨越多种检查类型，生成时必须考虑多次调用的组织方式；如果证据数量可能超过返回上限,需要在任务设计中控制时间范围。

环境指导 $K_E$ 记录每个工具的功能边界、典型使用模式与限制条件,并针对数据探索中的提问模式,归纳证据获取的典型流程。例如，"用药调整后HbA1c变化"任务的证据获取需要：先search\_medication\_requests获取用药列表,再read\_resource确认调整时间,然后search\_observations检索用药前后的HbA1c,最后对比数值。这些流程帮助生成阶段判断问题所需证据的复杂度与可行性。附录A.2给出环境探索的提示设计。

\textbf{探索指导的复用与边界。} 两类探索在初始阶段执行一次,所得指导 $K_D$ 和 $K_E$ 在后续所有患者的任务生成中复用。这意味着探索成本分摊到整个生成过程,而不是每个患者重复支付。然而,探索指导仍受限于其观察范围——如果新患者的记录结构或工具能力发生变化,指导可能需要更新。当前实验假设环境与数据组织在生成过程中保持稳定,跨环境泛化与指导演化留待未来工作讨论。

\subsection{知识引导的任务生成}


探索指导是跨患者的通用模式,但具体任务必须由当前患者的真实记录支撑。一个数据指导可能建议"围绕用药调整与指标改善提问",但当前患者的用药记录可能缺少时间字段、调整事件,或相关检查的时间分布不在合理窗口内。任务构建面临的核心矛盾是：如何将通用的临床模式实例化为有充分证据的具体问题?

我们设计两阶段生成机制回答这个问题。第一阶段从探索指导中筛选在当前患者有充分数据支持的模式。生成Agent读取完整患者轨迹、两类探索指导$K_D$和$K_E$、当前生成指导以及采样得到的题型难度方向,判断哪些临床关系在当前记录中具有所需的时间跨度、记录数量和字段完整性。

第二阶段围绕实际存在的证据构建问题、答案与引用。每条证据声明对应其来源记录实际支持的内容——检查结果包含数值、单位和时间,用药记录包含药物名称、剂量和开始日期,诊断包含疾病名称和确诊时间。跨记录的结论分别引用相关依据,区分记录事实与临床推断。对于事实查询("患者2023年6月的HbA1c是多少?"),参考答案明确数值、时间及单位;对于临床判断("患者的血糖控制是否改善?"),参考答案给出证据支持的判断与理由,并区分观察到的指标变化与对控制效果的推断。

这一设计确保任务的三个组成部分相互对应：问题指向明确的临床过程,证据来自环境中可验证的记录,答案建立在引用证据之上。记录不足以支持预期问题时,允许减少生成数量而不是降低要求。附录A.3给出任务生成的提示结构与输出格式。

\textbf{证据核验与任务筛选。} 生成完成后,核验流程从环境中重新读取引用记录,检查声明与来源是否一致。核验判断每条证据的支持性(记录内容是否确实包含声明的信息)、引用完整性(关键事实是否都有明确来源)以及整道任务的清晰度(问题是否明确、答案是否回应问题)。通过核验的任务进入独立解题与后续评价,未通过的任务记录失败原因但不参与策略更新——核验结果本身属于模型判断,需要与质量评分和解题表现共同分析才能区分任务缺陷的类型。

核验为生成任务提供一致的筛选依据。它无法取代人工评价,但可以在解题前识别明显的引用错误、证据不足和题意不清。实验报告核验通过率及其与后续质量评分的关系,以分析核验在流程中的实际作用。

\subsection{反馈驱动的策略进化}


单次生成难以预先确定哪些提问方式既有充分证据,又能提出适当的推理要求。一个看似合理的任务可能因证据不足无法完成,也可能对解题Agent要求过高。更重要的是,通过核验的任务仍可能集中于Agent已掌握的能力——比如大量"查询最近一次检查值"这类简单事实查询,却缺少需要整合多条记录、理解时序依赖的推理任务。

如何利用已生成任务的反馈持续改进?一个直接的想法是将解题失败的任务标记为"有价值",将完成的任务标记为"太简单"。但这种简化忽略了任务失败的多种原因:证据引用错误、问题表述不清、所需推理超出当前能力,甚至是环境故障。不区分这些原因而盲目调整策略,可能让生成朝错误方向演化。

MedEvolve 设计独立的反馈分析机制来解决这个问题。我们将任务质量、推理深度与解题表现分别评价,区分任务缺陷与能力不足,并将分析结果转化为策略更新。

\textbf{多维反馈收集。} 每个通过核验的任务接受三类评价。质量评价从事实准确性、临床合理性、证据充分性和题目清晰度四个维度打分(1-5分),判断任务本身的构建水平。推理深度标注任务完成所需的推理层级:1级为事实查询(直接读取单条记录),2级为单步推理(结合记录与临床知识判断异常),3级为整合推理(比较多次记录、识别趋势),4级为临床决策(综合证据权衡风险收益、提出方案)。解题表现记录固定Agent能否完成任务,并在失败时保留完整的尝试轨迹。

三类评价各自聚焦不同方面。一个任务可能质量高分、推理深度为3,但Agent未能完成——这说明任务本身合格,问题出在能力或证据检索策略上。相反,一个完成的任务如果质量评分低,说明核验未能充分识别缺陷,或任务虽可解但构建仍有改进空间。将三者联合分析,才能判断策略应该如何调整。

\textbf{反馈分析与归因。} 策略更新前,反馈分析汇总当前轮次的任务、患者轨迹、评价结果和失败案例,归纳质量问题的模式、推理要求的分布、失败的主要原因及改进方向。分析区分两类问题:生成缺陷(证据引用不完整、问题表述模糊、答案不回应问题)与能力挑战(证据检索困难、跨记录整合要求高、时间推理复杂)。

生成缺陷指向策略本身的改进:如果高比例任务因"证据不支持答案"而质量低分,生成指导应强调先确定事实依据再组织问题;如果题目清晰度普遍不足,指导应要求明确背景、时间视角和操作要求。能力挑战则影响题型配比:如果推理深度3-4级的任务完成率显著低于1-2级,配比调整可以适度增加中等难度任务,避免全部集中在高难度而导致大量失败。

重要的是,分析不会将所有未完成任务都视为"有学习价值"。质量评分低的失败任务可能本身存在缺陷,不应用于判断能力不足;完成率极低的某类任务可能超出当前合理范围,盲目增加其配比只会积累无效样本。反馈分析提供的是调整建议与问题诊断,策略更新采纳这些建议的同时保持生成的基本合理性。

\textbf{策略更新机制。} 策略$\theta=(g,w)$包含生成指导$g$与题型难度配比$w$。生成指导是文本形式的原则与约束(如"围绕用药调整提问时,必须确认调整前后各有至少一次相关检查"),题型难度配比是带采样权重的方向列表(如"事实查询:0.2,整合推理:0.5,临床决策:0.3")。

更新函数$U(\theta_r,F_r)$接收当前策略与反馈$F_r$(包含任务集合、评价结果、分析报告),返回新策略$\theta_{r+1}$。生成指导的更新结合反馈分析中的改进建议,修订证据选择、问题组织或答案构建的要求;题型配比的更新根据各难度层级的质量分布与完成表现,调整采样权重使后续任务在推理要求上更平衡。

解题Agent和评价标准在进化过程中保持固定,使逐轮变化主要反映生成策略的调整,而非评价尺度的漂移。策略在进化患者集合上迭代若干轮,最终在独立评测集合上与初始策略及其他方法比较。初始与最终策略的对比用于检验反馈更新的收益,逐轮结果用于分析质量、推理要求和完成表现之间的关系及策略调整的轨迹。

\section{实验}


\subsection{研究问题}


实验围绕两项方法贡献及生成任务的实际价值展开。

\begin{enumerate}
\item \textbf{生成质量与任务要求。} MedEvolve 能否在保持事实与临床合理性的同时，生成具有更丰富证据关系和推理要求的任务？
\item \textbf{探索与反馈的作用。} 探索所得知识与反馈驱动的策略更新如何影响任务质量、任务分布和完成表现？
\item \textbf{下游价值。} 使用生成任务积累的经验能否改善独立医疗基准上的解题表现？
\item \textbf{进化收益与成本。} 策略更新的收益如何随轮次变化，获得这些收益需要多少调用成本？

\end{enumerate}

\subsection{实验设置}


\textbf{研究设计。} 我们关注生成指导能否泛化到未见患者。如果策略更新仅仅记忆了特定患者的轨迹特征或答案模式,那么在新患者上的表现无法说明方法的有效性。因此将患者集合划分为进化集和独立评测集,两者的患者互不重叠,且同一患者的记录不跨集合。策略更新只使用进化集上的任务反馈,最终比较在独立评测集上完成。这确保观察到的改进来自可泛化的提问知识,而非对训练患者的过拟合。

实验在两个医疗环境中进行。PhysicianBench 提供真实的长程病历,轨迹长度从6个月到5年不等,记录密度高且类型丰富,包含完整的就诊、检查、用药和诊断历史。MedAgentBench 覆盖更多患者但轨迹相对较短（多数在1年以内）,疾病类型分布更广。两个环境的组合可以考察方法在不同数据特征下的表现：PhysicianBench 考察长程依赖与复杂证据整合,MedAgentBench 考察跨患者泛化与记录密度较低的场景。具体患者规模、轨迹长度分布与工具接口见附录B。

\textbf{对比方法选择。} 我们选择以下方法覆盖不同的任务构建思路,并验证数据探索与策略进化的必要性。

\begin{itemize}
\item \textbf{TaskCraft} 代表基于任务扩展的方法。从原子任务出发,通过深度扩展增加串行依赖、宽度扩展组合多个子任务,构建具有多步检索要求的 Agent 任务。与 MedEvolve 对比可以区分扩展机制与数据驱动探索的差异：前者依赖已有任务的组合与增强,后者从长程轨迹中识别新的提问模式。

\item \textbf{CuES} 的核心是好奇心驱动的环境探索。通过交互模式抽象任务,并以质量控制筛选候选。与 MedEvolve 的对比可以分离环境探索与数据探索的贡献：如果两者表现接近,说明环境探索已经足够；如果 MedEvolve 显著更好,说明对长程轨迹的理解带来额外价值。

\item \textbf{SelfRefine} 代表单批次内的迭代改进。生成初稿后,模型自评并依据反馈修订当前任务。这与 MedEvolve 的跨轮策略进化不同：SelfRefine 在每个患者内收敛,MedEvolve 跨患者积累改进经验。

\item \textbf{Workflow} 是固定流程的对照。执行定位、生成与内部检查三个阶段,但不使用探索指导,也不随反馈调整策略。这可以区分流程组织与知识引导的作用。

\item \textbf{SingleShot} 是单次生成的基线。读取患者轨迹后直接生成任务,没有探索、没有多阶段、没有反馈。这代表最简单的自动构建方式。

\item \textbf{EnvExplore} 是只保留环境探索的 MedEvolve 消融变体。执行环境探索获得工具指导,但不进行数据探索,且策略固定不更新。与完整方法对比可以考察数据探索和跨轮进化的共同作用；由于缺少单独的数据探索对照,无法分离两者的独立贡献,这一限制在讨论中说明。

\end{itemize}

所有方法在相同患者集合上生成任务,接受统一的核验流程、质量评价、推理深度标注与独立解题评测。评测使用固定的裁判模型、评分标准和解题 Agent 配置,环境或模型故障单独记录。方法间的资源预算按生成任务数量对齐,实际调用成本分别报告,以区分质量提升与额外投入的影响。各方法的内部流程、适配方式与主方法的详细配置见附录C。

\subsection{生成任务的质量与下游价值}


任务生成比较在独立患者集合上进行，按环境呈现质量评分、推理深度、证据结构、核验与完成表现。分析关注高推理要求是否伴随充分证据，以及低完成率究竟对应有效任务中的解题困难，还是生成质量不足。结合成本比较判断收益是否随资源投入仍然成立。

下游实验将各方法生成的任务用于医疗 Agent 的经验与策略改进，并在原始医疗基准上评价。任务集在下游改进前固定，同一环境与同一 Agent 设置下保持任务预算、初始状态和改进条件一致。基准题目、答案和评测反馈不参与任务生成或经验更新。

下游结果分别比较不同任务来源，并报告相对于 Agent 初始状态的变化。如果生成任务与基准共享患者记录，结论限定为同环境迁移；对未见患者的泛化需要独立患者评测支持。结果表、统计不确定性与分析待补充。

\subsection{探索与策略更新的贡献}


初始策略与最终策略在同一独立患者集合上比较，保留相同探索指导、评价流程与解题配置，以考察反馈更新是否改善生成结果。分析同时关注质量变化和题型难度分布变化，避免只依据完成率判断进化效果。

EnvExplore 保留环境探索与固定初始策略，与完整方法的比较反映数据探索和跨轮更新的共同作用。这一对照不能单独识别数据探索的贡献，独立组件效应需要相应控制组支持。最终消融配置、生成预算与结果待补充。

\subsection{进化过程与成本分析}


逐轮分析质量评分、推理深度、证据结构与完成表现，并结合生成指导和采样配比的变化解释任务分布如何调整。进化患者上的结果与独立患者上的结果分别呈现，检验观察到的变化能否在新患者轨迹中保持。

成本分析同时报告逐轮和累计投入，将任务质量与有效产出同探索、生成、策略更新及评测开销联系起来。进化曲线、成本结果与分析待补充。

\section{讨论与结论}


\subsection{局限性}


\textbf{数据与环境覆盖。} 任务生成依赖患者轨迹中实际存在的记录，以及环境接口能够提供的信息。记录缺失、时间字段不完整和不同机构的数据表达差异，都会影响可发现的提问情境。实验中的患者数量、临床场景与接口类型限定了结论的适用范围；跨患者划分的表现需要与跨机构、跨数据来源的泛化分别讨论。

\textbf{评价依据。} 四维质量评分与推理深度由模型裁判给出，三次评分取中位数仍可能保留共同的判断偏差。证据核验能够检查记录与声明的对应关系，临床合理性还涉及上下文与医学知识。质量分数、证据核验结果和解题完成情况因此分别报告，人工评估的覆盖与一致性需要结合最终评估安排说明。

\textbf{难度度量。} 推理深度描述任务所要求的推理层级，证据数量、记录类型数量和时间跨度描述引用材料的结构。记录类型计数依赖来源标识中的类型信息，时间跨度依赖可解析的记录时间；这些统计的完整性随环境而变化。解题表现还受到模型、工具设计、上下文容量与运行预算的影响，任务难度的比较需要保持相应条件一致。

\textbf{反馈与成本。} 生成策略更新依赖核验、裁判和解题反馈的可靠性。质量与难度各需要三次裁判调用，加上探索、生成和独立解题，构成多阶段调用成本。实验需要将任务收益与累计投入联系起来，并保留模型及环境故障记录，以区分策略效果与运行条件的影响。

\subsection{结论}


本文研究长程医疗轨迹环境中的自动任务构建，提出结合数据理解、环境交互与解题反馈的 MedEvolve 框架。其核心在于将探索所得知识用于出题，并通过任务反馈持续调整生成策略。评价体系分别衡量任务质量、推理深度、证据复杂度、完成表现与成本，以考察生成任务及策略更新的价值。

实验支持的主要结论及适用范围待补充。

Workflow、SingleShot 与 SelfRefine 在生成阶段读取患者轨迹材料，环境工具由公共核验和独立解题阶段使用。Workflow 的内部检查只筛选候选；SelfRefine 的反馈用于修订当前患者批次。EnvExplore 的环境指导在实验开始时获取，后续生成使用固定策略。所有方法的内部检查与公共评测分别记录，方法成本包含实际发生的内部调用。

\textbf{主方法配置。} 初始数据探索通过患者轨迹读取工具归纳数据指导，环境探索在独立环境实例中归纳工具指导，两者依次执行。单患者生成使用一次模型调用，输入完整轨迹、两种探索指导、当前生成指导与两个采样方向，输出任务批次。策略包含生成指导和带采样权重的题型难度方向。

公共核验逐条读取原始来源并检查证据声明，随后判断整道任务的支持性与清晰度。固定解题 Agent 只接收题目、患者和环境工具。完成评价接受合理等价答案，涉及写入操作时结合实际操作与环境状态判定。时间视角为可选任务属性，当前 PhysicianBench 配置未启用该属性。

\textbf{推理深度标准。} 评分依据任务要求及证据复杂度，以完成任务所需的推理确定层级。直接读取检验值、药物或事件为第 1 级；结合记录与临床知识判断异常或合理性为第 2 级；比较多次记录、识别趋势或整合多维信息为第 3 级；综合证据权衡风险收益、提出检查或治疗方案为第 4 级。引用数量与时间跨度作为结构特征单独记录。

\textbf{三裁判聚合。} 对任务 $i$ 的质量维度 $d$，三次裁判分别给出整数评分 $s_{i,d}^{(1)},s_{i,d}^{(2)},s_{i,d}^{(3)}$，任务最终得分为

\begin{equation}
s_{i,d}=\operatorname{median}\left(s_{i,d}^{(1)},s_{i,d}^{(2)},s_{i,d}^{(3)}\right).
\end{equation}

推理深度按同一规则聚合，质量评分范围为 1--5，深度层级范围为 1--4。评测记录保留三个原始分数与逐次评分依据。聚合要求三份有效裁判输出；模型调用或评分格式故障按评测失败记录，并保留已完成的评价阶段。

\textbf{自动复杂度计算。} 对任务引用的来源标识去重，得到证据集合 $S_i$，证据数量为 $|S_i|$。记录类型数量为 $S_i$ 中可识别类型前缀的去重数，例如 \texttt{Observation/123} 对应 \texttt{Observation}。证据时间跨度只使用任务引用来源在患者轨迹中的对应记录。设其中可解析的时间集合为 $T_i$，跨度为

\begin{equation}
\Delta_i=\frac{\max T_i-\min T_i}{1\text{ 天}}.
\end{equation}

无可解析时间时跨度记为缺失；只有一个可解析时间时跨度为 0。时间跨度保存在逐任务记录中，方法级复杂度汇总报告平均证据数量与平均记录类型数量。

\textbf{汇总口径。} 各质量维度在有评分的任务集合上分别计算均值、中位数、分数分布与高质量占比。对维度 $d$ 的有效评分集合 $I_d$，高质量占比为

\begin{equation}
H_d=\frac{\sum_{i\in I_d}\mathbf{1}[s_{i,d}\geq4]}{|I_d|}.
\end{equation}

难度汇总使用具有难度评分的任务，报告深度均值、四级分布和自动复杂度均值。核验与完成评价使用各自的覆盖数量，具体比率如表\ref{tab:ratios}。
