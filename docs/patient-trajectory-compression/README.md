# 数据探索与患者轨迹压缩

## 工具与访问范围

数据探索提供 list_patients、read_trajectory、compress_trajectory。压缩工具必须传入 patient_id，只能读取本次开放的训练患者缓存。每次有效调用执行一次模型请求，返回压缩轨迹及输入截断标记；原始缓存不被修改。压缩摘要只辅助数据探索，不替代出题和核验的原始病历。

## 模型与上下文

runtime.models.trajectory_compressor 独立配置模型、地址、认证变量、context_window 和 max_output_tokens。默认使用 DeepSeek V4.1 Flash，上下文 1,000,000 token，单次输出上限 131,072 token（包含模型推理输出）。切换模型时须同时配置该模型的上下文及输出上限。

压缩输入按上下文上限减去输出额度、提示词、JSON schema 和消息余量后截断。UTF-8 字节数作为文本 token 数的保守上界，避免依赖不匹配的模型分词器；因此实际使用的上下文可能小于模型上限。输入保持有效 JSON，截断时明确标记。输出由模型请求的输出 token 上限约束，不追加固定字符截断。

## 数据探索抽样

在训练患者内按实验固定随机种子抽取 50%，人数向上取整，保存抽样患者名单。只将这部分缓存开放给数据探索；环境探索、训练轮次与测试患者划分保持各自原有范围。

## 调用记录与验证

压缩调用的模型响应、用量和失败记录纳入数据探索结果。验证必填患者 ID、越界拒绝、一次调用、上下文截断、原始缓存完整性、失败处理及成本汇总；验证抽样可复现、测试患者隔离和训练轮次未被缩减。
