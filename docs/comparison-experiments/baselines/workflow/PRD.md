# Workflow 实施任务

## 目标与依赖

实现 SPEC.md 定义的固定阶段生成方向。依赖公共实验 section 提供共享生成入口、输出约束、运行结果汇总和预算约定。公共配置与分派由公共实验 section 集成，本 section 负责 methods/workflow/ 及必要的方法测试。

## 实施步骤

1. 在 methods/workflow/ 实现公共入口和本模块内的定位、内部检查输出结构；不修改共享 contracts.py。
2. 使用同一个 runtime.models['generator'] 完成定位、生成、内部检查，三个提示词各司其职。
3. 内部检查以本批候选位置对应判定，保留顺序并筛除失败候选；不得用主方法的反馈或策略做规划。
4. 聚合三个阶段的记录与用量；某阶段运行故障返回失败，明确不成立的候选可筛除为空批次。
5. 用一个患者跑固定流程及公共评测，检查各阶段依赖前一阶段产物。

## 最小验收

定位与生成的临床关注点对应，内部检查实际执行；检查失败题被筛除，阶段故障不伪造成有效题。全部内部调用计入生成成本。 验证关键机制和一个真实患者即可，不为字段转发或提示词字符串建立重复测试。

## 交付

实现提交、所需配置项、小样本任务和公共评测结果。真实调用使用已经授权的 gpt-4o-mini；对方法内部判定、公共核验和生成成本分别记录。接口冲突交给公共实验 section 处理。
