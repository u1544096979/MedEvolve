# 只读任务与患者并行设计

## 1. 实验范围与并发参数

同一次实验选择一个生成方法，允许该方法同时为多个患者生成任务。六个方法为 `medevolve`、`workflow`、`selfgen`、`singleshot`、`envexplore`、`taskcraft`，统一只生成、执行和评测查询任务。

查询任务的完成条件是读取既有患者记录并给出答案。临床建议、诊断解释及检查或用药建议可以作为回答内容，但不得要求提交医嘱、创建资源、更新或删除记录、保存结果到环境，或者调用模拟提交接口。MedAgentBench 的 POST 即使不持久化也禁止。任务生成、内置核验、环境探索、公共核验和独立解题均遵守此边界。

环境启动所需的种子加载由现有环境管理器完成，任务运行期间患者数据保持只读。实验结果、轨迹、日志与成本记录按现有机制保存到独立输出目录，不作为患者数据库写入或题目完成条件。

生成与公共评测独立调度。一个患者完成全部生成阶段、内置自检和候选筛选，输出最终 TaskBatch 后，立即释放生成名额；其任务进入公共评测队列，不占生成名额。

| 参数 | 粒度与占用周期 | 设置位置 |
| --- | --- | --- |
| `generation_concurrency` | 同时处于完整生成流程的患者数；从方法入口到最终输出或失败 | ExperimentConfig，正整数 |
| `evaluation_concurrency` | 同时处于完整公共评测流程的 task 数；从证据核验到完成判定或提前终止 | ExperimentConfig，正整数 |

例如 `generation_concurrency=5`、`evaluation_concurrency=2`：五名患者可以同时生成，两道 task 可以同时评测。患者 A 生成结束后，下一名患者即可开始，A 的任务可继续等待或执行评测。提高患者并发数不增加该运行的共享环境实例数。

显式配置优先；旧配置缺少字段时，两者分别回退到有效的 `MEDEVOLVE_RUN_CONCURRENCY`，未设置则沿用默认值 6。保存的 config.json 记录解析后的有效值。本方案只调度同一次实验的患者生成与 task 评测，不调度多个方法同时运行，不改变 Harness 进化流程。

## 2. 六方法适配

六个生成入口均已存在于 main；TaskCraft 的机制、提示与重试逻辑仍在 `codex/taskcraft-baseline` 迭代。方法入口存在不代表所有环境协议均已适配，按实际支持组合验收。

| 方法 | 单患者流程 | 环境使用与只读适配 | 并发边界 |
| --- | --- | --- | --- |
| `medevolve` | 按同轮策略生成最终任务 | 准备阶段探索共享实例；探索、生成与反馈使用统一只读说明 | 患者并行；同轮策略固定，本轮全部评测完成后才反馈并更新策略 |
| `workflow` | 定位两类任务 → 分类型生成 → 内部检查与过滤 | 逐患者生成不访问 Docker；各节点仅允许查询任务 | 保留五类候选池选两类、每类最多一题及内部顺序 |
| `selfgen` | 初稿 → 自检 → 必要修订 → 最终过滤 | 逐患者生成不访问 Docker；所有阶段使用统一只读说明 | 每患者独立预算与反馈；全部自检修订结束才释放名额 |
| `singleshot` | 一次调用，自主选题并输出 | 逐患者生成不访问 Docker；提示和公共输出校验限定只读 | 保留允许题型集合、两题可同类型和一次调用规则 |
| `envexplore` | 一次环境探索 → 固定指导与初始策略生成 | 只读探索共享实例，完成后逐患者生成不访问 Docker | 不重复逐患者探索，不加入数据探索或策略进化 |
| `taskcraft` | atomic 候选、width/depth 扩展、内置核验及最终选择 | 全部患者借用共享实例，仅绑定只读工具；各阶段只产生查询任务 | 每患者独立 Pipeline、Ledger、随机流、预算与候选池，保留内部调度及重试 |

缓存轨迹准备和一次性环境探索在患者生成前完成。TaskCraft 内置核验计入生成成本，不能替代公共评测。六方法统一输出 `execution_requirement="read_only"`，候选扩展、修订和过滤保留该字段；公共核验仍根据实际题面判断，不凭标签放行。

固定说明的唯一来源为 `environments/capabilities.py`，同时记录环境真实操作语义与本轮只读限制。六方法、探索、公共评测与解题接入同一说明，不复制 MedAgentBench POST 或 PhysicianBench 持久化文案。探索结果只能补充可用查询信息，不能开放提交或写入。

SelfGen 当前环境白名单、TaskCraft 当前工具协议支持需要按源码逐项核对。统一说明不能替代环境工具适配，未支持的组合不记为已通过。

## 3. 公共评测与轮次依赖

所有方法最终输出的每一道 task 均进入同一套公共评测。内部丢弃候选保留生成记录和成本，不进入公共评测；生成失败或零题输出记录尝试，不补造 task。

| 阶段 | 判定内容与行为 |
| --- | --- |
| 证据与整体核验 | 读取真实记录核验引用及事实，再核验题目、参考答案和只读完成条件；要求提交、写入或依赖新增数据的任务判 invalid，停止后续评测 |
| 质量与难度 | 保留事实准确性、临床合理性、证据充分性、题目清晰度，以及推理深度和证据复杂度；质量与难度各三次评分并取中位数 |
| 独立解题 | 仅接收题目、患者标识、决策点与只读工具，不接收参考答案或完整缓存轨迹；记录回答与查询轨迹 |
| 完成判定 | 检查回答是否满足题目要求及证据支持；不要求 POST、资源新建或数据库状态变化 |

整体核验的既有模型调用同时检查只读边界，不增加单独分类调用。历史任务可以缺少执行要求字段，但必须通过同一题面核验；历史提交或写入任务不能进入本轮解题。越界任务记录为任务范围不匹配，不能计作临床难度。

每道 task 单独占用一个评测名额。生成与评测可以重叠；MedEvolve 保留轮次屏障，本轮全部生成与评测结束且结果保存后，才汇总反馈并更新策略。初始策略评测与最终评测保留既定阶段顺序。

## 4. 共享环境与患者隔离

### 4.1 实例复用

同一次运行、同一环境与固定种子配置，只维护一个共享逻辑实例，覆盖轨迹准备、只读探索、TaskCraft 生成、证据核验与独立解题。实例在首次需要时创建，运行结束或取消后释放；患者生成结束只释放其生成名额和环境借用，不关闭仍供其他任务使用的实例。

| 环境 | 环境原始能力 | 本轮 Agent 开放能力 | 一个逻辑实例的容器构成 |
| --- | --- | --- | --- |
| PhysicianBench | 查询与真正持久化的 POST | 仅查询，创建资源等写工具禁止 | 一个 FHIR 容器 |
| MedAgentBench | GET 与不持久化的模拟 POST | 仅查询，模拟 POST 同样禁止 | 一个 FHIR 容器 |
| FHIR-AgentBench | 已适配原生工具仅查询 | 已支持的只读工具 | HAPI 与 PostgreSQL 两个容器 |

因此，单次 PhysicianBench 或 MedAgentBench 实验可由一个 Docker 承载全部患者；FHIR-AgentBench 复用一个逻辑实例，但该实例包含两个容器。不同环境、管理服务地址或种子不能混用，同一运行固定其配置。多个独立实验进程不自动共享实例。

扩展现有 `evaluation/session.py` 会话覆盖所有阶段，统一共享键为环境名、管理服务地址和种子配置。沿用 `MEDEVOLVE_MAX_INSTANCES` 的逻辑实例额度作为创建上限；单环境运行只申请一个实例，无需按 task 申请独立实例或增加写入任务调度。

### 4.2 只读工具与患者边界

提示、任务核验和执行工具同时约束只读。函数工具只开放环境显式声明的查询工具，FHIR 客户端在发出修改请求前拒绝；MedAgentBench 原生动作只允许 GET 与 FINISH，POST 在接受模拟请求前即拒绝。只读限制覆盖环境探索和解题，不能只应用于 TaskCraft 生成。

共享服务不共享患者上下文。每次借用创建独立工具绑定、允许患者 ID、模型上下文、预算、轨迹和输出。保留现有患者访问范围检查，不修改共享对象的患者字段，不共享 TaskCraft Pipeline、Ledger 或随机对象。临时文件、日志和输出路径按 run、患者及 task 隔离。

### 4.3 生命周期

同键并发首次申请只创建一次；创建中、存活与释放中的实例均计入既有额度。创建失败释放预留；患者或 task 失败不关闭其他任务的共享实例。取消或不可继续的错误先停止调度，等待全部借用收尾，再关闭运行会话。释放失败记录具体实例及错误，不虚报清理完成。

## 5. 输出与验收

方向采样在创建并发工作前按患者原始顺序完成；TaskCraft 保留患者派生随机流，SingleShot 保留自主选题。任务编号、患者方向和结果归属不受完成顺序影响，不要求真实模型并行文本与串行完全相同。

生成结束立即保存 attempts、生成记录和最终 tasks；各 task 评测完成后保存其结果，通过稳定 task ID 关联。保留现有输出锁，按患者下标和题下标组织结果，避免并发覆盖文件或成本记录。

验收覆盖六方法各自已支持的环境组合：两个并发上限分别生效、生成名额及时释放、只读题面核验正确、所有阶段无修改请求、五患者查询共享同一实例、患者上下文与文件隔离、方法预算和内部顺序保持、MedEvolve 轮次屏障及取消清理正确。TaskCraft 在研变更合入后重新执行机制与公共并发回归。
